# TraceGuard

视频盗版风险监控项目的最小可运行版本。**R1～R10（R4 分 A/B）共 11 个规则项均已提供运行及配置入口**；R1 目前支持中、高档，一般档仍缺协议顺序模型。支持规则配置与版本管理：

**选择检测基准时间 → 按各规则窗口读取特征 → 生成告警与证据快照 → 查看详情 → 保存人工复核 → 刷新后仍可查询。**

进入“规则配置”可启停规则、修改阈值及档位分数、试算样例、保存版本，并载入旧版恢复。R4B 的注意档支持两组条件满足任一组；R1 的未接一般档明确说明，详见 [规则接入与配置说明](doc/规则接入与配置说明.md)。

## 启动

需要 Node.js **24.12 或更高的 24.x 版本**（使用内置 TypeScript 和 SQLite）。

```powershell
npm ci
Copy-Item .env.example .env.local
# 编辑 .env.local，填写 ClickHouse 连接信息及密码，再启动
npm start
```

打开 <http://localhost:3040>。开发时使用 `npm run dev`。程序和示例配置均默认使用 ClickHouse，需先配置连接信息并确保网络可达。已有 `.env.local` 时保留原文件，不重复复制覆盖。离线体验时可显式设置 `DATA_SOURCE=demo`，该模式使用程序生成的样例，不查询数据库。

演示批次可设置 `AUTO_DETECT=1`，服务启动后立即检查第一个预设窗口，之后每隔 `AUTO_DETECT_INTERVAL_SECONDS` 秒检查下一项（默认 15 秒）。八个验证场景各检查一次，成功窗口复用已保存结果，失败窗口在下一轮重试；全部完成后停止。总览显示进度、下一项和最近检查结果。轮巡仅覆盖固定合成验证批次，服务停止后不运行，也不代表实时监控或自动处置；手动运行检测入口仍可使用。

默认选“失败集中”，窗口为北京时间 `2026-10-23 14:00–14:10`：现有 ClickHouse 合成验证数据有 200 条事件，150 失败、50 通过，失败率 75%，得到 **A=25 / S=0**。重复运行同一窗口复用结果，不重复生成告警，不覆盖已有复核。

首次创建数据库时仅启用 R7；其余规则可在页面开启。已有数据库保留保存的配置。检测采用启动瞬间的配置快照；新配置用于新的检测，旧告警、证据和复核不改写。同一窗口的规则版本变化后允许重新检测，结果独立保留。

各规则共用所选基准起点后 10 分钟的结束时间，再按自身长度回溯：R3 为 5 分钟，R4A 为 30 分钟，R5 为 1 小时，R8 为 24 小时，其余为 10 分钟。结果和告警保存实际窗口。超出验证批次的规则单独显示数据不足，不影响窗口仍在范围内的规则。

## 连接 ClickHouse

复制 `.env.example` 为 `.env.local`，设置 `DATA_SOURCE=clickhouse`，填写 ClickHouse 地址和凭据，再重启服务。环境变量也可以直接传入启动进程。`.env.local` 和运行数据库均已加入 Git 忽略列表，示例不包含密码。

```dotenv
DATA_SOURCE=clickhouse
CLICKHOUSE_HOST=<clickhouse-host>
CLICKHOUSE_PORT=8123
CLICKHOUSE_DATABASE=da
CLICKHOUSE_USER=default
CLICKHOUSE_PASSWORD=填写本地密码
TENANT_ID=980107c0ab
RUN_ID=tg_980107c0ab_20261016_20261023_v1
AUTO_DETECT=1
AUTO_DETECT_INTERVAL_SECONDS=15
```

使用同一“失败集中”窗口可检测现有合成验证事件。切换“未知结果”场景默认读取 17:00 窗口，UNKNOWN 不当作失败，样本不可计算时不创建告警。切换到正常场景后没有命中或没有观测都不会生成告警，两种结果分别展示。

ClickHouse **只读**，不建表、不写入、不修改原始数据。针对固定、不可变验证批次，先限定租户、批次、场景、`SYNTHETIC` 数据、所需阶段和窗口，再按稳定 `event_id` 去除采集重复。R7/R8 使用窄字段聚合；其他规则共享有界事件查询，并按需读取媒体、来源覆盖、历史授权及播放前态。该优化不能直接复用于有历史修订的生产事件。查询有超时、单线程、256 MiB 内存及输出限额（事件／媒体最多 25,000 行，聚合最多 1,000 行），超限失败，不截断后评分；失败不回退演示结果。

## 持久化与范围

- 告警、触发时特征、检测记录和复核历史由服务端 SQLite 保存，默认 `.runtime/traceguard.<DATA_SOURCE>.sqlite`；演示模式与 ClickHouse 模式隔离。
- 复核依据必填；使用请求幂等键和版本检查，重复请求不重复追加记录，多标签页覆盖会被拒绝。
- R7 分档沿用计分卡 v0.2；N=PASS+FAIL 至少 100。一般：F≥30 且失败率≥20%；注意：F≥100 且≥50%；高危险：F≥300 且≥80%。只取最高档。
- R7 只进入异常分 A，嫌疑分 S 为 0。视频访问异常不能证明盗版；验证数据不代表生产分布。
- R1、R2、R3、R4B 在缺少相应缓存、下载或共享策略核验时只计算 A，命中时 S 显示“—”。演示租户 `980107c0ab` 已配置禁止下载/预取、禁止账号共享及 5 分钟 Key 缓存前提，自 2026-10-23 起新检测中符合条件的 R1/R2/R4B 可计算 S；R4A 按可信事件时点授权范围计算 token 的异常及嫌疑贡献。R5、R6、R8、R10 尚未关联同活动主要嫌疑证据，S 为 0。当前按单规则展示，不计算 R2/R6/R10 跨规则总分。R9 始终是 0 分标签。缺少必要证据时显示数据不足。
- 告警保留原生主体，R3/R5/R8 为认证观众，R4A/R4B 为 token，其余保留对应视频局部。不把 token 风险归为绑定观众本人行为，也不把观众跨视频分数复制给每个视频。
- 当前每条命中规则分别形成告警及自身贡献分，不把多个告警加成个人或视频总分。24 小时主体画像、同事实合并、组内封顶和反复加分尚未实现。
- 当前固定租户和验证日期范围。相同基准时间、配置版本及提取代码版本复用已成功结果；演示批次支持服务进程内自动轮巡。迟到修订、滚动生产窗口片段合并、生产调度、登录、多租户权限、R1 一般档尚未实现。
- 配置保存采用 SQLite 事务、版本冲突检查及请求幂等键。字段、操作符与分支结构由服务端约束，主要规则最高 50 分，辅助规则最高 15 分；不支持自定义 SQL 或可执行表达式。
- 本版本只允许本机监听，适合本地演示。SQLite 是首期运行依赖；未来按实现方案将业务持久化替换为 MySQL，数据访问集中在 `server/store.ts`。

## 工程结构

```text
server/             TypeScript API、有界事件提取、规则计算与配置校验、SQLite 存储
web/                原生 HTML/CSS/JavaScript，风险总览、告警中心、规则配置、取证报告
sql/runtime/        R7/R8 聚合、客户端事件、媒体/覆盖/授权历史/播放前态的参数化 SQL
sql/features/       保留原有 TG-F00～12，应用不批量执行
scripts/            保留原有数据生成和验证工具
test/               计分与特征边界、配置版本、API、幂等、持久化、复核和上游失败测试
doc/                原型、规则、数据说明与完整实现方案
```

```powershell

```

测试使用独立临时 SQLite 和内存/模拟 HTTP 输入，不访问真实 ClickHouse、不影响实际告警。真实数据联通测试需单独启动 ClickHouse 模式，通过页面或 `/api/detections` 运行一次。

主要 API：`GET /api/health`、`GET /api/overview`、`GET /api/rules`、`GET /api/alerts`、`GET /api/alerts/{id}`、`GET /api/alerts/{id}/timeline`、`POST /api/detections`、`POST /api/alerts/{id}/reviews`。规则接口为 `/api/rules/{id}/history`（GET），以及 `validate`、`simulate`、`configurations`、`rollback`（POST）。写接口仅接受同源 JSON 请求。

## 事件回放

告警详情内嵌事件回放：授权、内容、环境三条轨迹共用一条可拖动的时间游标，可播放或用方向键微调。游标停留时，侧栏同步显示已观察事实、支持的风险方向、尚不能确认与建议下一步四块内容，读数区给出该时点的累计请求、去重内容与 token / 密钥状态。

回放按告警主体与实际窗口从同一验证批次重新取数：token 有效期来自授权快照，内容量按分片映射与 CDN 完整响应统计，环境按可信 IP 与归一化客户端类别分组。仅使用已有采集记录，不补画虚构事件；请求点超出画布密度时做等距采样显示，计数与内容量不受影响。接口为 `GET /api/alerts/{id}/timeline`。

## 取证报告与模型辅助研判

租户业务前提由 `config/business-policies.json` 显式配置，当前租户 `980107c0ab` 使用 `BP-980107c0ab-v2`：禁止下载、预取及账号共享；Key 缓存上限 300 秒，到期重新获取；仅允许同一观众发起续期，不扩大原授权范围，续期须保存授权快照。该配置用于监控研判，不修改视频服务端的实际访问控制。验证策略从 2026-10-23 00:00（北京时间）生效。

修改业务策略时同步提升版本并重启服务，应用会保留旧策略历史并将新版本同步到本地 SQLite。新检测冻结策略快照，策略版本和计分逻辑参与缓存标识；旧告警/报告保持原快照，需重新检测和生成报告才能看到新嫌疑分。数据和业务前提满足时，R1/R2/R4B 按各自单规则档位计算 S=A；R4A 继续按越权访问证据计算，辅助规则不直接叠加嫌疑分。其他未配置的租户不会继承该策略。

打开 `http://localhost:3040/#reports`，或从告警详情点击“生成取证报告”。选择同租户、同来源、同一次检测的 1～8 条告警，生成包含主体、实际窗口、特征、触发配置、规则解读、人工复核快照的报告。所有规则贡献独立展示，不计算跨规则总分。旧运行未保存数据批次时明确显示未知，后续运行会保存批次。

同一证据快照重复生成复用报告；原告警新增复核后重新生成会形成新版本，旧报告内容保持不变。可校验 SHA-256、下载证据 JSON，或点击“打印 / 保存 PDF”使用浏览器的 PDF 保存功能。正文摘要对应规范化 JSON 的 UTF-8 字节，不是 PDF 文件摘要，也不是第三方存证。归档需要人工填写说明，已归档版本锁定模型生成和审核；归档不等于确认侵权。

可选接入阿里云百炼，在本机 `.env.local` 配置（不要提交密钥）：

```dotenv
LLM_WORKSPACE_ID=你的业务空间ID
LLM_REGION=cn-beijing
LLM_MODEL=deepseek-v4.1-flash-1017
LLM_API_KEY=你的API密钥
```

配置后重启 `npm start`。使用业务空间级 `https://{workspace}.{region}.maas.aliyuncs.com/compatible-mode/v1/chat/completions` 接口，Bearer 鉴权、关闭思考、JSON Object 输出。参考[百炼 DeepSeek 文档](https://help.aliyun.com/zh/model-studio/deepseek-api)和[兼容接口文档](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)。

模型只接收数值特征、规则口径和主体别名，不发送真实主体/视频 ID、IP、UA、请求引用、原始日志或人工备注。点击“查看脱敏输入”可检查实际输入结构。模型结果保留模型名、提示词版本、输入/输出摘要、用量和证据引用；无效引用或新造数值会被拒绝。模型解释仍可能出错，必须人工采用或不采用；采用后将其摘要用作报告结论，完整研判单独留存，不改变原告警状态或分数。未配置、超时或生成失败时仍可使用规则报告，不会伪造模型结果。“下载研判记录”导出独立附录和审核信息。

新增接口：`GET/POST /api/reports`，`GET /api/reports/candidates`、`GET /api/reports/config`，`GET /api/reports/{id}`；`verify`、`evidence`、`llm-context`、`analyses` 为 GET 子资源，`analyze`、`archive` 为 POST；人工审核为 `POST /api/reports/{id}/analyses/{analysisId}/review`。数据继续存放在本地 `.runtime/` SQLite，保持忽略，不要提交给同事；同事用自己的配置和日志生成报告。
