# 取证报告与辅助研判

目标是把已保存的风险事件整理成内部可核查材料。页面沿用纸张报告排版，保留“生成 → 校验/导出 → 模型草稿 → 人工审核 → 归档”的最小流程。

## 证据与版本

报告选取同一次成功检测、同租户、同来源的 1～8 条告警。冻结检测元信息、告警完整特征/配置、规则贡献和生成时人工复核记录；以 E01 等编号引用事实。不同主体和规则保留各自范围，不直接加总分数。历史运行缺少批次 ID 时不借用当前环境配置补写。

正文使用键排序的规范化 JSON，计算 UTF-8 字节 SHA-256。下载证据 JSON 即对应这些字节。相同快照复用报告；原告警复核变化后重新生成形成新版本。PDF 使用浏览器打印，可保存为 PDF；PDF 排版字节不属于正文摘要。本地哈希用于一致性检测，不承诺防篡改、可信时间戳或法律效力，也不包含完整原始日志。

## 模型边界

脱敏输入仅包含数值特征、指标定义、规则口径、业务前提状态和主体/视频别名。不外发真实 ID、租户、IP、UA、URL、请求引用、原始日志或人工备注。别名只在单份输入内有效。模型不调用工具、不联网补证、不执行封禁/吊销，也不修改评分或复核状态。

使用百炼业务空间级 Chat Completions 接口与指定模型，密钥来自本机 `.env.local`。单次请求 60 秒，响应最大 128 KiB，关闭思考，JSON Object 输出，不自动重试或切换模型。输出必须为五个字段：摘要、发现、其他解释、未知项、建议补查；每条附有效的 E 编号。服务端校验结构、引用和数值边界，并拒绝自动处置、总分/概率等越界措辞。该校验不能证明自然语言解释正确，人工仍须核对。

特别区分：R1 是缺少必要授权步骤后仍获准访问，不是媒体分片丢失；R2 是内容拉取倍率，不是播放器播放速度。嫌疑业务前提未核验，与特征计算所需数据质量不足是不同状态。

模型调用单独留存任务，记录模型、提示词版本、脱敏输入及其摘要（首轮历史联调仅留存摘要）、内容摘要、状态和用量。重复请求 ID 复用原任务；显式重新生成使用新请求 ID，不自动产生费用。服务重启将未完成任务标为失败。上游失败只保留通用错误与 HTTP 状态，不保存供应商诊断正文或密钥。

## 审核与归档

模型结果初始为待审核草稿，页面与规则解读区分。人工填写依据后选择采用或不采用；采用后使用最新已采用草稿的摘要作为报告结论，完整研判单独留存。原证据 JSON 摘要、原告警评分和状态不改变。证据正文、模型内容和审核信息可以分别下载核对。

归档需要填写说明；生成中不可归档，已采用附录校验失败不可归档。归档后锁定该版本的模型生成和审核。更新后的原告警复核可用于生成新报告版本。当前操作者为本地工作空间标识，尚未提供账户认证或签名式审核身份。

## 实现与验证

- `server/reports.ts`：快照、规范化 JSON、证据解释、模型输入白名单。
- `server/model.ts`：百炼 HTTP、输出校验、模型草稿类型。
- `server/store.ts`：报告/任务/审核/归档持久化与幂等。
- `web/reports-ui.js`、`web/reports.css`：报告页面、证据定位、审核和打印样式。
- `test/reports.test.ts`：跨运行隔离、哈希导出、修订与重启、篡改阻断、脱敏、引用/数值约束、真实 HTTP 协议模拟、失败、幂等与人工审核。

远端 ClickHouse 仍只读。新增内容仅写入应用本地 SQLite。
