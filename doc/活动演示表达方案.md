# TraceGuard 活动演示表达方案

日期：2026-10-23。依据用户补充的目标客户与案例，以及 [计分卡 v0.2](计分卡-v0.2.md)、[特征 SQL 编号对照](特征提取SQL编号对照.md)和[演示案例测试数据](演示案例测试数据.md)。案例一以当前运行版中的合成验证数据和本地告警为演示依据。

## 1. 产品定位与核心价值

### 面向谁

面向保利威平台上重视视频版权保护、却缺少专职风控人力的客户，例如课程培训机构和内容服务商。

### 产品提供什么

产品目标是汇集分散的播放、鉴权及内容访问日志，识别异常行为，并形成可解释、可追踪的视频版权侵权风险线索，帮助客户优先核查真正需要关注的账号和视频。

### 视频开场建议

> 客户重视课程版权，却未必有专人每天分析播放和鉴权日志。即使请求经过正常授权，也可能存在异常获取、账号共享或长时间持续访问。TraceGuard 将这些分散的行为证据整理成可以理解、追踪和复核的风险线索，让缺少风控人力的客户也能开展有依据的排查。

“相对准确”是产品目标。演示通过正常行为和异常行为对照、身份归因、未知状态保留等方式表达减少误判的设计；未在客户标注数据上完成验证前，不给出准确率或减少误报的百分比。

客户日志接入尚未完成，因此上面的采集与分析描述是目标业务链路。当前演示使用预置数据与本地模拟，不能声称已经持续接入客户数据并自动产生告警。

## 2. 三个案例及可支持的结论

### 案例一：正常授权后的高速获取、机械访问与工具特征

**故事：**合成观众 `sim_rapid_pull_case_supplement_viewer` 对视频 `sim_course_01` 正常取得 token、清单和 key。在北京时间 2026-10-23 12:00–12:10，同一会话按规律访问全部 720 个加密分片，访问的去重内容相当于 7,200 秒；多个请求阶段出现 `ffmpeg/7.0` 工具特征。

**演示标题：**“授权正常，内容获取行为仍值得核查”。

**证据顺序：**

1. 在告警中心搜索 `sim_course_01`，打开本地 R2 告警 `TG-D1CE59B67FF5`：10 分钟内成功访问 7,200 秒去重媒体内容，速度比 12，当前 A50 / S50。
2. 查看同次检测的 R6 告警 `TG-ED50F87D996C`：720/720 个分片，覆盖率与递增比例均为 100%，间隔 CV 为 0，当前 A15 / S0。
3. 查看 R10 告警 `TG-149E817EF92D`：723 次工具特征请求、3 类请求阶段，当前 A15 / S0。三条告警属于同一观众、视频与检测窗口，编号来自当前本地快照，重检后可能变化。
4. 补充说明 token、清单和 key 的成功记录，以及 720 次对应的 CDN 完整响应。演示租户已配置禁止下载和预取；当前 R2 的嫌疑分以此业务前提为准。

| 特征/规则 | 适用条件 | 展示结论 |
| --- | --- | --- |
| TG-F03 / R2 高速拉片 | 固定窗口、唯一媒体量可计算，达到阈值且已排除合法下载/预取 | 异常集中获取内容 |
| TG-F08 / R6 机械访问 | 媒体序列完整、样本足够，覆盖、递增与间隔规律达到阈值 | 同一访问片段具有机械性，作为辅助证据 |
| TG-F12 / R10 工具特征 | 实际客户端 UA/签名可识别，排除已知合法工具 | 存在工具访问特征，作为辅助证据 |
| TG-F02 / R1 链路异常 | 另有协议要求、有效期、完整回溯及可判定的异常事实 | 本例授权步骤正常，不纳入组合计分 |

**关于授权间距：**本例 Key 响应与首个 TS 请求只相隔 0.7 秒，两者 UA 同为 `ffmpeg/7.0`。因此不能把它讲成“正常访问 Key 后 UA 切换、等待很久才拉片”的链路异常案例，也不命中 R1。正常授权只用于说明“获准访问”与“内容获取行为正常”是两个不同判断。

**关于“所有分片”：**本组合成数据有清单总片数、720/720 个不同分片及对应的 CDN 完整响应，可说“服务端完整返回了该清单下的分片”。这仍不证明客户端已在本地解密、破解或传播。

**分数表达：**当前应用分别展示 R2 的 S50，以及 R6、R10 的 S0；尚未生成跨规则总分。按计分卡 v0.2 候选口径，R2 50 分与 R6 15 分同类封顶为 60，再计入同活动的 R10 15 分，可演算出 S75。演示时把 75 明确标为候选组合计算，不能称为当前告警已输出的分数。

**结论措辞：**“同一观众正常获准访问后，又在短时间内按机械节奏集中获取整门课程的分片，且出现工具特征。建议优先核查该账号的内容使用情况。”不能由这些记录直接确认本地破解或传播。

### 案例二：账号在不同环境间短时间反复使用

**故事：**业务假设是观众 A 将账号分享给 B；产品实际观察到的是同一账号活动在明显不同的网络和客户端环境中使用。

**演示标题：**“疑似账号共享，定位到具体环境和时段”。

建议展示两个明确区分的路径：

| 数据情形 | 使用哪些证据 | 结论边界 |
| --- | --- | --- |
| 同一账号下，同一个有效 token 在两个明显不同环境反复交错 | TG-F06 / R4B；需各环境多次通过记录、交错跨度及有效授权；能够可靠关联账号时才归因到该账号 | 支持凭证共享/泄漏线索，不知道具体哪两个人在使用 |
| 同一账号分别登录并获得不同 token | TG-F07 / R5 解释环境变化；若有可信且业务不允许的多视频重叠，可用 TG-F04 / R3 | 不适用“同 token 多环境”规则；单纯环境变化不足以确认账号共享 |

用 A、B 两条环境轨迹显示“IP＋归一化客户端类别＋实际请求点”。有充分日志时可显示 A→B→A→B 的交错；不要把两次相距较远的登录画成同时使用。

正常对照可以是手机网络切换或同一人顺序切换设备。合法代理、企业出口、允许的多端使用等需要按客户业务规则排除。IP/UA 是环境线索，不等于物理设备或自然人身份。

个人计分卡展示“账号使用风险线索”；只有 token 内绑定观众 ID、缺少可靠账号活动归因时，保留关联凭证信息，个人评分显示身份待核实。无需恢复已移除的 token 计分卡 Tab。

### 案例三：课程内容被长时间、几乎无间断访问

**故事：**同一账号一天内连续访问大量课程，内容量和持续性明显偏高。

**演示标题：**“超长持续访问，进入人工核查”。

证据应分开显示：

- 有成功内容访问的分钟数；
- 去重媒体内容量，避免重复请求或音视频轨重复累计；
- 活跃分钟的连续段和最长请求间隔；
- 如有可信 PLAYBACK_STATE，显示播放状态区间，并按有效期和下一状态截断；
- 如已具备可比历史，再显示其与账号自身历史或同类课程使用模式的差异。未有基线时不展示“超过 99% 用户”等数字。

当前 TG-F10 / R8 支持持续访问特征，现有 R8 候选档位同时要求活跃分钟与内容量，例如高档为 M≥960 分钟且 C≥16 小时。连续段、最大间隔可作解释；“远超正常学习强度”需要有比较依据。

**录屏推断：**网络日志无法直接看见屏幕录制。合法连续学习、后台自动播放也可能产生类似记录。因此将“可能存在录制活动”放在人工核查假设中，不展示“已识别录屏”或“已看完全部课程”。只有 R8 等辅助证据时，按当前 v0.2 口径不单独建立盗版嫌疑分。

建议核查账号使用人、企业培训安排、自动连播设置与内容授权；后续若获得真实外传样本或可核实的内容溯源证据，再支持更强判断。

## 3. 更直观的证据表达

### 推荐：同一告警详情中的事件回放

当前运行版从风险大盘和告警中心进入案例，不增加专用案例入口。以下事件回放和证据开关是后续交互设计，尚未出现在当前运行版中；静态[交互原型](TraceGuard-交互原型.html)中的独立计分卡也不能当作本地告警的现行汇总结果。

回放使用一个可拖动的时间游标，画面分为三条轨迹：

1. **授权轨迹：**token、key、续期、失效与撤销，标明每个时点的授权事实。
2. **内容轨迹：**访问的视频与媒体区间，将固定时间内获取的内容长度可视化；不同阶段分开显示。
3. **环境轨迹：**可信 IP/客户端组合及事件点，显示交错和切换，避免用跨度直接冒充持续活跃。

游标停在某个事件时，侧边同时显示“已观察事实、支持的风险方向、尚不能确认的部分、建议下一步”。没有对应明细的演示数据不补画虚构事件，使用明确标注的模拟回放或只展示已有汇总。

### 补充一：证据开关，解释为什么产生这个判断

允许在独立模拟区暂时忽略一条证据，比较分数和理由如何变化。例如忽略工具特征后，仍有高速获取；只留下时间异常或持续访问时，不自动建立更强的侵权嫌疑。

这是计分规则的解释模拟，不是删除历史证据，也不表示该证据的真实因果作用。切换结果必须由现有计分引擎计算，不能手填一个“可信度百分比”；历史告警保持触发时快照。

### 补充二：同一异常表象，切换正常与异常对照

在同一详情中提供一个简短对照：当前行为与合法下载、正常设备切换、服务失败分别差在哪里。将不同点落到可观察字段上，避免只用红绿颜色宣布结论。

三分钟演示优先采用事件回放和一个对照案例。证据开关可用于答辩互动，避免将录屏时间耗在过多操作上。

## 4. 区分故障、异常与侵权风险的具体做法

系统先计算可观察的访问异常，再根据独立证据给出风险方向。A 是异常分，S 是通过准入检查的盗版嫌疑分，S=0 不代表已经确认安全。

| 对照情形 | 观察到什么 | 当前如何表达 | 还需核查什么 |
| --- | --- | --- | --- |
| 视频失败异常，优先排查服务 | 10 分钟内同来源同阶段 500 次鉴权，450 次失败；假设没有其他准入嫌疑证据 | R7 高档，视频 A=50、S=0；展示“访问异常，优先排查服务/授权配置” | 错误码、用户分布、时间集中度、服务监控、配置变更；仅失败率不能确诊故障 |
| 正常授权后高速获取 | token/key 有效，短窗口内容量异常，且有可核实的机械访问或工具特征 | R2 为主要线索，R6/R10 按上下文辅助；展示“异常内容获取，待核查授权用途” | 是否允许下载、预取，以及身份与响应证据是否可靠 |
| 大量失败但有授权范围外尝试 | 历史授权快照明确目标不在允许范围，失败事件与 token/目标视频可关联 | 视频侧 R7 仍只表达异常；token 范围外事实按 R4A 独立判断，再检查个人归因 | 是否授权配置错误、业务范围变更、自动重试或批量探测；相同事实不重复加分 |

这套区别的价值是提供可解释的分流：服务排查、账号使用核查、内容获取核查。故障也可能与恶意行为同时发生，不能把所有事件强制分成互斥类别。只有已完成业务核验，才能标记为已确认故障或已确认违规。

## 5. 三分钟活动演示的取舍

不建议三个案例都完整操作。推荐主案例一占主要时间，案例二和三用简短切换展示覆盖能力，再保留故障对照来解释判断质量。

| 时间 | 内容 | 核心表达 |
| --- | --- | --- |
| 0:00–0:20 | 客户困境与产品定位 | 客户缺少风控人力，但希望有依据地保护课程版权 |
| 0:20–1:20 | 案例一检索 R2 告警，查看同窗口 R6/R10 证据与评分 | 正常授权之后仍可以识别异常内容获取；区分当前 S50 与候选组合 S75 |
| 1:20–1:45 | 案例二与三简短切换 | 覆盖共享使用和持续访问；明确线索与结论的距离 |
| 1:45–2:15 | 视频失败对照 | 高异常不自动变成高盗版嫌疑，降低误伤风险 |
| 2:15–2:40 | 保存一次复核依据与下一步 | 客户能从发现线索走到有据可查的核查交接 |
| 2:40–3:00 | 价值和完成度 | 已有预置演示及特征实现；下一步完成客户数据接入与真实效果验证 |

规则编辑器保留在产品中，主视频可只点明“规则可回放调整”，详细编辑和证据开关留到答辩。

## 6. 结尾话术与完成度

> TraceGuard 希望把原本依赖人工逐条查日志的工作，转变为系统整理线索、解释证据、提示核查方向。让没有专职风控团队的客户，也能把有限时间花在更值得关注的问题上。我们已完成预置场景的交互演示和基础特征实现，下一步完成客户日志接入，打通持续计算与告警闭环，再用真实业务反馈验证并校准效果。

当前可展示的实现：风险大盘、告警中心、规则编辑器，合成数据的按窗口检测、独立规则告警及人工复核记录，以及仓库中的标准表、公共视图和聚合特征 SQL。静态原型还可展示候选计分卡的交互演算。

尚需完成或验证：客户来源映射、采集完整性与身份关联；在线窗口调度、跨规则汇总；真实数据上的阈值校准和效果评估。客户数据接入是首要未完成项，不能因已有合成数据和本地告警就声称生产链路已打通。
