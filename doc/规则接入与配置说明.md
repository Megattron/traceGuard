# 规则接入与配置说明

R1～R10（R4 拆 A/B）共 11 个规则项均已接入运行与配置。R1 支持中、高档，一般档仍缺协议顺序模型。阈值仍是《计分卡-v0.2.md》的历史回放候选值。

## 规则能力与限制

| 规则 | 窗口与主体 | 计算与限制 |
| --- | --- | --- |
| R1 授权链路异常 | 10 分钟；观众＋视频／会话 | 唯一分片上判断必要步骤缺失，默认 30 片→25 分；同一请求同时缺有效授权和密钥，100 片→50 分。有效 token 快照算授权存在，不因没有 TOKEN_CREATE 日志误判；key 回溯有效期、清单回溯原签发时间，覆盖不全不可计算。一般档顺序模型未实现；缓存策略未核验时命中 S 为“—” |
| R2 高速拉片 | 10 分钟；认证观众＋视频 | 按内容版本合并媒体区间，C/600；要求可靠身份和完整来源／媒体映射。下载或预取策略未核验时命中 S 为“—” |
| R3 同时多视频播放 | 5 分钟；认证观众 | 可信 PLAYBACK_STATE 按下一状态及有效期截断，合并同视频相邻区间，求同一视频子集持续至少 60 秒的并发数。不累加多个不同视频对的重叠时间；合法多路策略未核验时命中 S 为“—” |
| R4A 跨授权范围复用 | 30 分钟；token | 先选事件时点最近授权快照，再判断撤销、过期及范围；缺失或冲突快照不当作范围外。按 video＋request_ref 合并鉴权／响应。低中档要求全部未获准；任一范围外获准或有字节响应进入高档。仅关联实际成功的目标视频，不复制 token 分给绑定观众 |
| R4B 同 token 多环境使用 | 10 分钟；token | 只用事件时点有效 token 的客户端通过记录。环境为可信 IP＋客户端类别，忽略 SDK 小版本。一般档两个环境各 2 次；注意档三个环境各 5 次，或明显不同环境对交错至少 60 秒、区间双方各 5 次；高档同一环境对交错、IP 和客户端类别均不同、区间双方各 10 次。次数及跨度可配置；合法共享策略未核验时命中 S 为“—” |
| R5 设备与网络环境变化 | 1 小时；认证观众 | 至少 20 条有效客户端 TS 事件，统计可信 IP 与归一化客户端类别，排除后端及已知代理；必要身份／环境未知时不可计算。IP/UA 不是物理设备数，S 暂为 0 |
| R6 分片机械访问 | 10 分钟；观众＋视频／会话／序列 | 覆盖率、递增比例、间隔 CV；保留真实重试，不拼接会话、清晰度和轨道；完整性或先后不明不可计算，S 暂为 0 |
| R7 视频鉴权失败异常 | 10 分钟；视频＋来源／阶段 | N=PASS+FAIL，UNKNOWN 单列，最小 N 可配置；S 固定 0 |
| R8 长时间高强度访问 | 24 小时；认证观众＋单一来源 | 活跃分钟集合及跨视频／内容版本媒体区间并集。同内容重试、清晰度和轨道不增加唯一时长；ClickHouse 内聚合全天窄字段，不下载全天明细，要求完整覆盖；S 暂为 0 |
| R9 夜间访问标签 | 10 分钟；视频 | 北京时间，默认 [02:00,06:00)，可跨午夜；0 分标签不创建告警 |
| R10 脚本或工具特征 | 10 分钟；观众／视频／会话／签名 | 清单／密钥／媒体三类规范阶段，同请求同阶段去重，排除后端及已知健康检查；UA 可伪装，S 暂为 0 |

已接入表示可以对符合前提的数据计算，特定窗口仍可能数据不足。TS 鉴权通过不等于实际传输、观看、解密或传播；响应字节也不证明对外传播。当前业务配置没有完整的合法下载、缓存、多路和共享策略，不能宣称这些业务例外已核验。

## 多窗口语义

页面选择基准十分钟起点，以其后 10 分钟为所有规则共同结束时间，各自向前回溯。例如基准 2026-10-23 14:00：

| 规则 | 实际窗口 |
| --- | --- |
| R3 | 2026-10-23 14:05—14:10 |
| R4A | 2026-10-23 13:40—14:10 |
| R5 | 2026-10-23 13:10—14:10 |
| R8 | 2026-10-22 14:10—2026-10-23 14:10 |
| 其他 | 2026-10-23 14:00—14:10 |

每项结果与告警保存实际窗口。窗口超出批次的规则单独显示 WINDOW_OUTSIDE_BATCH，其他规则继续。R1 补读相关 token 的前置授权；R3 补读窗口前仍有效的播放状态。均不读共同结束时间后的事实。

## 配置与历史

新数据库仅默认启用 R7，已有数据库保留原配置。可启停、修改前提参数／阈值／分值、校验草稿、样例试算、保存版本、载入旧版后保存恢复。R4B 注意档两组条件为“或”，组内为“且”。服务端固定字段、操作符和分支结构，主要规则最高 50、辅助最高 15 分，不执行任意表达式或 SQL。

样例试算假设质量前提成立，不创建告警。新配置用于后续检测，正在运行的检测保持启动快照；历史告警和复核不改写。载入旧版只生成草稿，保存后形成新版本，并发修改有版本检查。

每条规则按原生主体独立生成告警。仍未实现主体总分、同事实合并、证据组封顶、反复加分和辅助特征的嫌疑准入关联。R5 与 R4B 可分别展示，但不直接加成主体分；token 绑定 viewer 不等于实际请求者。

## 运行与验收

ClickHouse 只读，限定固定租户、不可变批次、场景及 SYNTHETIC 类型；配置和业务状态写本地 SQLite。事件先筛选再去重的优化仅适用当前不可变批次，生产修订数据需要重新设计。

查询单线程、12 秒、256 MiB；输出最多 25,000 条事件／媒体或 1,000 条聚合结果，超限失败，不用截断数据评分。R4B 超过 100 个环境时返回数据不足，避免环境对组合使应用长时间阻塞。

npm run check 包含类型检查及 27 项自动测试，覆盖新增规则正反例、时点授权／过期、联合环境对、连续并发、唯一分片、全天集合、多窗口越界、分支校验、配置生效、旧证据冻结和持久化。

ClickHouse 合成数据验收：R4A 范围外访问 A50/S50；R4B 多环境 token A50/S—；正常数据 R3、R5 可计算且未命中。R8 持续访问样本唯一媒体只有 7,200 秒，未达 8 小时门槛；R1 missing_chain 只有 20 片，未达 30 片。高速拉片场景可同时触发 R1 A25、R2 A50、R6 A15，各条贡献不直接相加。不能为制造演示命中而降低默认阈值。
