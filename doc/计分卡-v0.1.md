# TraceGuard 计分卡 v0.1（讨论稿）

日期：2026-10-22。依据《计分规则.md》当前的 10 类规则设计。本稿中的阈值、窗口与分值都是历史回放候选，尚未通过真实数据校准，不是生产配置，也不是盗版概率。

## 1. 计分原则

- 分别为人、视频、token 计算总分。同一租户内，人才是观众或个人账号，不能把客户/租户账号当作一个人。
- 主要规则按一般 10 分、注意 25 分、高危险 50 分；辅助规则按一般 5 分、注意 10 分、高危险 15 分。辅助规则的高档表示该信号更集中，不足以单独将主体定为高危险。
- 每条规则只取满足条件的最高一档，不累加各档分数。未命中计 0 分；数据不足记为“不可判断”，不能据此认为安全。
- 相同证据只计一次。单事件标签、重复请求条数、同一命中连续被窗口计算到，都不逐次累计加分。
- 当前总分反映当前有效观察窗口内的异常。高危险表示应优先复核，不自动等同于盗版或自动封禁。

## 2. 特征和观察口径

| 符号或术语 | 口径 |
| --- | --- |
| 人 | 租户内的观众或个人账号；实际访问者与 token 绑定观众无法区分时，标明身份依据 |
| 视频 | 同一租户下的同一视频；版本、清晰度、音视频轨道需按媒体时间轴正确处理 |
| C | 观察窗口内成功内容访问对应的去重媒体时长，单位秒；同一视频相同媒体区间不因重试或切换清晰度重复计入，不同视频可相加 |
| speed_ratio | 完整 10 分钟观察窗口内 C / 600；不使用单个突发请求首尾间隔作分母 |
| 成功内容访问 | 需明确数据层次：TS 鉴权通过只证明准许访问；CDN 实际传输按其日志结果确认，均不直接证明实际观看 |
| 并发视频数 K | 5 分钟窗口内，持续至少 60 秒同时活跃的不同视频数；不是窗口内曾访问过的视频数 |
| 活跃分钟数 A | 24 小时窗口内有成功内容访问的不同分钟桶数；属于网络访问活跃，不等于实际观看分钟数 |
| UA 类别 | 归一化到客户端/操作系统类别，避免把 SDK 小版本变化当作不同设备；UA 数不等于设备数 |

并发区间优先由可信播放器状态/心跳支持；只有 TS 请求时只能估计，不能把首末请求之间全部视为持续播放。需要使用估计并发时，应独立校准活跃区间的超时口径。

## 3. 主要规则计分卡

下表的每一档均须满足该行“前提”；任一时刻只取最高满足档位。各窗口均基于事件发生时间，建议每分钟评估一次。

| 编号／规则 | 原生判断主体 | 前提与窗口 | 一般：10 分 | 注意：25 分 | 高危险：50 分 |
| --- | --- | --- | --- | --- | --- |
| R1 授权链路异常 | 人 + 视频／播放会话 | 10 分钟；按终端实际协议定义必要步骤；日志完整、延迟已收敛，且排除合法缓存、授权续期和合法预取 | 存在必要步骤顺序或间隔异常，但尚未发现缺失必要授权步骤后的成功内容访问 | 至少 30 个不同分片获准访问，但缺失一个必要的前置授权步骤 | 至少 100 个不同分片获准访问，且同时缺失授权凭证获取和必要密钥获取步骤；两类缺失均有完整日志与有效期回溯支撑 |
| R2 播放速度异常（拉片速度） | 人；可按人 + 视频细分 | 10 分钟；C ≥ 1,800 秒；跨视频统计时先按视频去重媒体时长再相加 | 3 ≤ speed_ratio < 5 | 5 ≤ speed_ratio < 10 | speed_ratio ≥ 10 |
| R3 同时多视频播放 | 人 | 5 分钟；按持续重叠区间判断；排除业务允许的多路播放 | K = 2 | K = 3 | K ≥ 4 |
| R4 授权异常复用 | token | 30 分钟；已知 token 在各请求时刻的真实授权范围；正常续期和同视频多 play_id 不算异常 | 至少 10 次使用同 token 尝试访问授权范围之外的内容，涉及至少 2 个不同视频，均未获准 | 至少 30 次上述尝试，涉及至少 5 个不同视频，均未获准 | 至少一次使用同 token 访问授权范围之外的视频且获准或成功传输；以可信的授权范围及结果记录为依据 |
| R7 视频失败请求过多 | 视频 | 10 分钟；同一请求阶段、同一来源及统计口径；N ≥ 100；R = F / N | F ≥ 30 且 R ≥ 20% | F ≥ 100 且 R ≥ 50% | F ≥ 300 且 R ≥ 80% |

R1 的必要步骤必须由真实播放协议确定。不能仅凭“没有看到 key”就认定缺失必要步骤；观察窗之前的有效授权/密钥也要纳入回溯。缺少这些前提时不授予相应分值。

R4 的前两档是授权范围外的批量复用尝试，不表示已泄露内容；高档表示已观察到越权使用成功。如果 token 按业务设计允许多视频访问，允许范围内的访问不计分。只有 token 自带的 viewer 信息时，只能确认凭证绑定关系，不能证明是谁发起访问。

R7 的高分是视频访问异常严重程度，可能由系统故障引起，不代表视频或访问者被确认盗版。N/F 仅包含明确结果，未知结果另列。

## 4. 辅助规则计分卡

辅助规则最高仅 15 分，其单独命中不应让主体进入注意或高危险等级。这里的分档用于表示信号集中程度，不能替代与主要规则的交叉验证。

| 编号／规则 | 原生判断主体 | 前提与窗口 | 一般：5 分 | 注意：10 分 | 高危险档：15 分 |
| --- | --- | --- | --- | --- | --- |
| R5 设备与网络环境频繁变化 | 人 | 1 小时；至少 20 条有效访问事件；使用归一化客户端 UA 类别，排除已知业务代理和日志来源差异 | 不同 IP ≥ 3 且 UA 类别 ≥ 2 | 不同 IP ≥ 5 且 UA 类别 ≥ 3 | 不同 IP ≥ 8 且 UA 类别 ≥ 4 |
| R6 视频片段访问过于规律 | 人 + 视频／播放会话 | 10 分钟；完整分片请求序列、至少 30 个不同分片、分片清单完整；按同一媒体分片序列分析 | coverage ≥ 0.5 且 monotonic ≥ 0.9 且 CV ≤ 0.5 | coverage ≥ 0.8 且 monotonic ≥ 0.95 且 CV ≤ 0.2 | coverage ≥ 0.95 且 monotonic ≥ 0.99 且 CV ≤ 0.1 |
| R8 长时间高强度观看（访问） | 人 | 24 小时；完整访问记录；同时检查活跃分钟数 A 与去重请求内容时长 C | A ≥ 480 分钟且 C ≥ 8 小时 | A ≥ 720 分钟且 C ≥ 12 小时 | A ≥ 960 分钟且 C ≥ 16 小时 |
| R10 脚本或工具特征 | 单次请求；可按人 + 视频／会话聚合 | 会话内最近 10 分钟；同一工具 UA；排除已知合法工具调用 | 单事件命中工具 UA 特征 | 工具 UA 出现在至少 2 类请求阶段，且工具请求数 ≥ 20 | 工具 UA 出现在至少 3 类请求阶段，且工具请求数 ≥ 100 |

R5 只表示网络与客户端类别变化，现有日志不能给出稳定的物理设备数量。单纯 IP 变化不满足本稿条件。

R6：coverage = 成功访问的唯一分片数 / 对应清单的总分片数；monotonic = 有效相邻请求对中分片序号递增的比例；CV = 请求间隔标准差 / 均值。先去除采集重复，再按请求时间分析，保留实际重试；区分不同轨道和清晰度。间隔均值为 0 或样本不足时不可判断 CV。

R8 反映持续网络访问和内容请求量，不证明一直在观看，也不能通过采样缺失断言用户休息。相同内容在 24 小时内的重复访问不增加 C，但保留重试/复看记录供分析。

R10 的阶段指播放地址、密钥、TS 等不同请求类型，不是重复请求次数。工具 UA 可以合法使用或伪装，最高档仍只给 15 分。未归属到个人的单次请求只保留事件级命中，不归给视频全部观众。

## 5. R9 异常时段活跃：0 分标签

继续沿用已讨论的定义：事件可归属到视频，按租户业务时区发生在预定义低活跃时段内，就标记 is_off_hours=true。[02:00, 06:00) 仍为候选时段。

本规则不设置 10/25/50 或 5/10/15 分档：一次凌晨访问没有足够依据区分一般、注意和高危险。无论标记了多少条请求，标签本身均为 0 分，不逐事件累计。

后续按人计算夜间请求数、视频数、活跃分钟数、最长连续活跃段、夜间访问占比及历史偏离。当前可将夜间作为 R2、R8 等规则的解释维度，不因同一行为同时发生在夜间而再加一遍分。本稿不新增独立的“异常时段高活跃”计分规则。

## 6. 总分计算：先分主体，再合并证据

### 6.1 人的总分

在时刻 T，按各规则自己的窗口重算当前分数。窗口未结束或必要日志尚未到齐时，只能输出初判状态。规则先在自己的粒度检测：人 + 视频／会话规则对同一人的多条命中取最高分；人维度规则在该人的完整范围上重算，不能把多个视频或多个 token 的分数相加。

token 风险不直接复制给观众。只有可明确关联到该观众的凭证/访问记录时，才由相关证据参与个人卡；标明其反映的是实际访问行为还是本人关联凭证的暴露风险。身份关联不明时只保留 token 卡和待归因记录。

| 证据组 | 包含规则 | 计分方式 |
| --- | --- | --- |
| A 授权链路 | R1 授权链路异常、R4 授权异常复用 | 取最高分，最多 50 分 |
| B 内容拉取 | R2 拉片速度、R6 机械访问、R8 长时间高强度访问 | 取最高分，最多 50 分 |
| C 多路使用与环境 | R3 多视频并发、R5 环境变化 | 取最高分，最多 50 分 |
| D 客户端 | R10 脚本或工具特征 | 最多 15 分 |
| 辅助标签 | R9 异常时段活跃 | 0 分 |

```text
A = max(R1, R4)
B = max(R2, R6, R8)
C = max(R3, R5)
D = R10

个人总分 = min(100, A + B + C + D)
```

这些证据组是首版避免明显重复计分的保守分组，并不表示各组在统计上独立。比如同一次高速拉片同时呈现机械顺序，不能分别把 50 和 15 分相加。同一事实被多条实现规则命中时，即使跨组，也需按证据归属保留一次计分；没有新增客户端证据时，不将速度本身再解释成 R10 工具特征。

### 6.2 视频的总分

当前已定义的原生视频计分规则只有 R7；R9 是 0 分标签。因此首版直接采用：

```text
视频总分 = R7，取值为 0 / 10 / 25 / 50
```

不为了覆盖 0～100 刻度而硬加尚未定义的视频规则。视频的夜间访问量、关联高风险观众数、最高关联个人分数可以另外展示，但不加入视频总分，也不将多个观众分数相加。

同一个观众访问 100 个视频，不意味着每个视频都继承该观众风险；某视频失败异常，也不意味着全部观众继承视频分数。视频卡应命名为“视频访问异常分”，避免被理解为盗版已发生的概率。

### 6.3 token 的总分

首版原生 token 计分规则为 R4：

```text
token 总分 = R4，取值为 0 / 10 / 25 / 50
```

同一 token 的多次命中取最高档，不按请求数或关联视频数重复加分；相关数量已经包含在分档条件中。正常续期、多 play_id、授权范围内多视频访问均不加分。

## 7. 主体总分等级

三个主体使用相同的分数区间方便展示，但分别表示个人访问/关联凭证风险、视频访问异常、token 使用异常；不能据此直接比较不同主体的盗版概率。

| 总分 | 主体等级 | 解释 |
| --- | --- | --- |
| 0 | 未命中计分规则 | 当前可计算规则没有可计分命中；仍可能存在夜间等 0 分标签，不等于确认安全 |
| 1～24 | 一般 | 存在弱信号或轻度异常，保留明细并观察 |
| 25～49 | 注意 | 存在较明显异常或多项辅助信号，进入复核候选 |
| 50～100 | 高危险 | 至少一项强规则达到高档，或多组异常叠加，应优先复核；视频侧同时排查服务故障 |

单规则严重程度与主体等级是两层概念：例如工具特征达到高档得 15 分，个人整体仍为一般；授权复用达到高档得 50 分，token 或可归因的个人达到高危险。

另设证据状态，不把它混进分数：初判、复核、数据不足。主体同时展示“分数 + 等级 + 证据状态 + 未能计算的规则”。完全无可计算数据时显示“— / 数据不足”，不能显示“0 / 正常”。

## 8. 时效、采样与重复命中

- 当前分数按各规则窗口每分钟重算，命中条件消失后相应分数退出；历史告警、特征快照保留。日内最高分可另列，不能当作当前分数，也不逐日累加。
- 对同一主体、同一规则、同一窗口中的重复评估只更新当前档位，不产生新的加分。告警合并/通知冷却与分数计算分开。
- TS 的 1/10 采样若满足相应采样假设，可用“样本成功请求数 × 10 秒 / 0.1”估算请求内容量；该值包含重试，不是去重媒体覆盖时长 C，必须以不同特征名保存，不能冒充全量 C。
- R2 只有采样估算时，可在独立校准的样本口径下给初判，首版最高暂记 25 分；缺少采样机制与样本门槛校准时记为不可判断。10 分钟成功样本数 ≥ 18 仅是候选最低门槛，不保证估算可靠，也不直接替代本稿的全量条件。
- R3 只有请求推断并发时，需校准活跃区间并标为初判，首版最高暂记 25 分。尚无有效并发口径时不可判断，不能使用视频去重数替代。
- R6 不以 1/10 样本计算准确覆盖率与完整间隔规律，首版等待全量日志；R8 的上述阈值也以完整访问记录和去重内容量为依据。样本可展示已观察到的活跃下界，不能套用全量阈值形成确定结论。
- R7 的 100/30/20% 等数字只对应全量示例；采样分子分母必须同口径，样本阈值需单独回放校准。CDN 复核失败率前需确认其是否包含同类失败以及失败结果语义。
- 部分初判规则达到主体高危险时仍显示“高危险 / 初判”；不因总分高就将证据状态改为确认。

## 9. 算分示例

| 场景 | 分数组成 | 总分与等级 |
| --- | --- | --- |
| 正常观众凌晨访问一次视频 | R9 标签 0 分，其余无命中 | 0 分，未命中计分规则；保留夜间标签 |
| 工具 UA 高档，环境变化高档，其余无命中 | 客户端 15 + 环境组 15 | 30 分，注意；不能仅据此认定下载 |
| 10 分钟去重请求 4,800 秒内容，呈机械规律高档，工具 UA 一般档 | R2=25、R6=15，同组取 25；R10=5 | 30 分，注意 |
| 10 分钟去重请求 7,200 秒内容，机械规律高档，工具 UA 高档 | R2=50、R6=15，同组取 50；R10=15 | 65 分，高危险；前提为完整证据 |
| 同上但只有已校准的采样速度初判，机械规律无全量数据 | R2 初判封顶 25，R6 不可判断，R10=15 | 40 分，注意 / 初判，并列出缺失项 |
| 某视频 10 分钟 500 次 TS 鉴权、450 次失败 | R7：N=500、F=450、R=90%，得 50 | 视频 50 分，高危险；需归因或排查故障，观众不继承分数 |
| 同 token 访问已确认授权范围外的视频且获准访问 | R4=50 | token 50 分，高危险；观众归因另外判断 |

## 10. 这一版的验证范围

先回放合法倍速、预加载、缓存密钥、切换清晰度、移动网络、企业 NAT、合法工具调用、夜间正常学习及服务故障等样本，再验证批量拉片、越权复用、并发多视频等样本。校准每条规则的命中率、主体数量、误报原因以及不同档位的分布。

重点确认 10/25/50 与 5/10/15 的组合是否便于人工理解，50 分高危险阈值是否符合复核能力，以及采样初判与次日复核之间的升降级情况。本稿尚未完成这些数据验证。
