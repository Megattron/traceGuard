# TraceGuard 计分卡 v0.2（讨论稿）

日期：2026-10-22。基于《计分规则.md》及本轮讨论，修订 [v0.1](计分卡-v0.1.md)。本稿替代 v0.1 的计分方案，保留 v0.1 供对照；所有数字阈值、观察窗口、分值和封顶值仍为历史回放候选，未完成生产数据校准。

## 1. 本轮明确的目标与调整

最终需要分别回答：某个视频被盗版的嫌疑程度，以及某个个人/观众账号实施盗版行为的嫌疑程度。规则本身的分数先表达异常程度，只有能够支持对应主体和嫌疑方向的证据，才进入主体嫌疑分。分数不是盗版概率。

| 项目 | v0.2 决定 | 原因 |
| --- | --- | --- |
| 异常与嫌疑 | 同时保留异常分、盗版嫌疑分及嫌疑方向 | 视频鉴权故障可能很异常，但不能直接当作盗版证据 |
| 单项主要规则高档 | 可以单独使主体进入高危险；证据状态另列 | 多环境复用 token、越权访问成功等不必等待另一项异常才提升等级 |
| token 多环境使用 | 在 R4 中增加独立子规则 R4B，作为主要规则 | 同 token 被明显不同环境使用，直接支持共享/泄漏嫌疑和盗版尝试线索 |
| 同类规则计分 | 同事实去重，不同特征可加分，同类证据设置上限 | 全部相加会重复计分，全部取最高又会丢失互补信息 |
| 跨时段反复出现 | 合并同一次异常的重复检测；独立异常再次发生时增加反复异常分 | 滑动窗口反复命中不等于出现多次新行为 |
| 严重程度与证据状态 | 分开呈现，不统一把初判封顶为 25 分 | 可以存在高危险初判，但不能把估算或日志缺失描述为已核实事实 |

## 2. 输出的分数和归因边界

### 2.1 每张主体卡展示什么

| 输出 | 回答的问题 | 使用范围 |
| --- | --- | --- |
| 异常分 A，0～100 | 观测到的访问/凭证使用行为有多异常 | 原生规则及正确归属到该主体的行为证据 |
| 盗版嫌疑分 S，0～100 | 这些证据能在多大程度上支持该主体的盗版嫌疑 | 通过嫌疑方向、主体归因和上下文检查后的证据 |
| 嫌疑方向 | 为什么产生盗版嫌疑 | 盗版尝试、凭证共享/泄漏、内容异常获取，可多选 |
| 证据状态 | 支撑该分数的特征是否已被可靠观测 | 初判、特征已核实、数据不足；缺失规则另列 |
| 人工复核状态 | 审核工作是否已完成 | 待复核、已复核；与特征是否已核实分开 |

0 分表示当前可计算规则没有对应的可计分命中，不表示确认安全。没有可计算或可归因的依据时显示“— / 数据不足”，不以 0 分代替。嫌疑方向不分别计算后相加；同一事实即使支持多个方向，仍只计一次。

### 2.2 个人、视频与 token 的边界

- **个人/观众账号**：优先表达该主体可归因访问行为的盗版嫌疑。客户/租户账号包含多人时不能视为一个人。账号活动也不能直接证明某个自然人亲自操作。
- **凭证关联风险**：token 中的 viewer 信息只证明凭证绑定关系。仅凭这个字段，不把多环境使用直接归为绑定观众本人实施盗版；在其画像中另列“关联凭证风险”。实际请求者无法确认时，个人行为嫌疑分为“— / 身份待核实”。
- **视频**：盗版嫌疑依据该视频自身的具体访问、授权暴露或异常获取证据。不能将关联个人的总分复制到视频，也不能把所有观众的分数相加。
- **token**：表达凭证共享/泄漏、跨授权范围复用等嫌疑。正常续期、同视频多个 play_id、业务允许的多客户端使用不直接计分。

例如：同 token 出现在 iOS 与 Android 等不同客户端环境，可以核实复用事实并将 token 评为高危险；如果 token 强绑定一个视频，该视频也有凭证暴露嫌疑。但 token 所绑定的观众可能是共享者，也可能是凭证被盗的受害者，不能直接给本人盗版行为下结论。

## 3. 统一观察口径

| 特征 | 定义 |
| --- | --- |
| 视频范围 | 同一租户下的同一视频；清晰度、版本、音视频轨道按媒体时间轴正确处理 |
| C | 观察窗口内有成功内容访问记录的去重媒体时长，单位秒；同一视频同一媒体区间不因重试或切换清晰度重复计入，不同视频可相加 |
| speed_ratio | 完整 10 分钟窗口内 C / 600；不用单次突发请求首末间隔作分母 |
| 成功结果层次 | 分开记录鉴权通过、CDN 成功传输；二者均不直接证明已观看、已解密或已对外传播 |
| 并发视频数 K | 5 分钟窗口中持续至少 60 秒同时活跃的视频数；不能用窗口访问过的视频数替代 |
| 活跃分钟数 M | 24 小时内有成功内容访问的不同分钟桶数；是网络访问活跃，不等于实际观看分钟数 |
| 环境 E | 请求来源 IP 与归一化客户端/操作系统类别的组合；明显不同环境优先指 iOS、Android、桌面客户端等类别差异，不把 SDK 小版本变化视为不同设备 |
| IP 与 UA | IP、UA 都是环境线索；IP 数和 UA 数均不是物理设备数，UA 也可以伪装 |

使用不同日志来源时保留 source、event_time、ingest_time、采样率/方式和结果语义。只去除采集重复，实际重试应保留；计算 C 时再按媒体区间去重。

## 4. 规则异常程度计分卡

主要规则按一般 10 分、注意 25 分、高危险 50 分；辅助规则按一般 5 分、注意 10 分、高档 15 分。每个子规则只取满足条件的最高档，不把三个档位相加。未命中为 0，无法判断时记录缺失条件。

### 4.1 主要规则

| 规则 | 主体与前提 | 一般：10 分 | 注意：25 分 | 高危险：50 分 |
| --- | --- | --- | --- | --- |
| R1 授权链路异常 | 人 + 视频／会话；10 分钟；按真实终端协议确定必要步骤，排除合法缓存、续期和预取；日志完整、延迟收敛，并回溯窗口前有效授权/密钥 | 必要步骤顺序或间隔异常，尚未观察到缺失必要步骤后的成功内容访问 | 至少 30 个不同分片获准访问，但缺失一个必要前置授权步骤 | 至少 100 个不同分片获准访问，且同时缺失授权凭证和必要密钥获取步骤，两类缺失均有完整日志支撑 |
| R2 拉片速度异常 | 人；可按人 + 视频细分；完整 10 分钟；C ≥ 1,800 秒 | 3 ≤ speed_ratio < 5 | 5 ≤ speed_ratio < 10 | speed_ratio ≥ 10 |
| R3 同时多视频播放 | 人；5 分钟；有可靠活跃区间并排除业务允许的多路播放 | K = 2 | K = 3 | K ≥ 4 |
| R4A 跨授权范围复用 | token；30 分钟；已知各时刻真实授权范围，排除允许的多视频访问 | 至少 10 次尝试访问范围外内容，涉及至少 2 个视频，均未获准 | 至少 30 次上述尝试，涉及至少 5 个视频，均未获准 | 至少一次范围外视频访问获准或成功传输，有可信授权范围及结果记录 |
| R4B 同 token 多环境使用 | token；10 分钟；token 相同且有效；环境差异可信，排除来源字段差异、合法代理和业务允许的客户端共享 | 至少 2 个不同环境，各有至少 2 次鉴权通过记录 | 至少 3 个不同环境，各有至少 5 次通过记录；或至少 2 个明显不同环境交错使用跨度 ≥ 60 秒、各至少 5 次通过记录 | 至少 2 个明显不同环境交错使用跨度 ≥ 60 秒，且各至少 10 次通过记录；来源 IP 和归一化客户端类别均不同 |
| R7 视频失败请求过多 | 视频；10 分钟；同一阶段/来源/结果口径，N ≥ 100，F 为失败数，R=F/N | F ≥ 30 且 R ≥ 20% | F ≥ 100 且 R ≥ 50% | F ≥ 300 且 R ≥ 80% |

R4A、R4B 是原 R4“授权异常复用”的两个子规则。原 R4 的概览分为 max(R4A, R4B)，概览分不再次加入总分；两子规则若表达不同事实，可分别进入对应证据组。同一事实则去重。

R4B 的交错使用要求两个环境在重叠时间范围内均有多次实际记录，跨度至少 60 秒，不能只凭两个各出现一次、相距较远的请求。此处判断的是凭证被多个环境反复使用，不据此认定真实播放并发或物理设备数。iOS→Android 等明显客户端差异比单纯更换 IP 更强；仅 IP 变化仍由 R5 作为辅助信号处理。

R1 的顺序/间隔异常若没有进一步的越权或必要授权被绕过的事实，仅计异常分；R1 缺失必要步骤但内容获准访问的事实，才可支持授权绕过嫌疑。日志缺失、有效期未回溯或协议不要求该步骤时，不授予相应分值。

R7 的 50 分可以使视频访问异常达到高危险，但不能单凭这个结果让视频盗版嫌疑也达到高危险；它可能是服务故障。缺失结果不当作失败，无法解析到具体视频的请求也不强行归属。

### 4.2 辅助规则

| 规则 | 主体与前提 | 一般：5 分 | 注意：10 分 | 高档：15 分 |
| --- | --- | --- | --- | --- |
| R5 设备与网络环境变化 | 人；1 小时；至少 20 条有效事件；UA 归一化，排除已知业务代理和日志来源差异 | IP ≥ 3 且 UA 类别 ≥ 2 | IP ≥ 5 且 UA 类别 ≥ 3 | IP ≥ 8 且 UA 类别 ≥ 4 |
| R6 分片机械访问 | 人 + 视频／会话；10 分钟；完整序列、至少 30 个不同分片、清单完整，按同一分片序列分析 | coverage ≥ 0.5，monotonic ≥ 0.9，CV ≤ 0.5 | coverage ≥ 0.8，monotonic ≥ 0.95，CV ≤ 0.2 | coverage ≥ 0.95，monotonic ≥ 0.99，CV ≤ 0.1 |
| R8 长时间高强度访问 | 人；24 小时；完整访问记录；同一内容在该窗口内不重复计入 C | M ≥ 480 分钟且 C ≥ 8 小时 | M ≥ 720 分钟且 C ≥ 12 小时 | M ≥ 960 分钟且 C ≥ 16 小时 |
| R10 脚本或工具特征 | 单次请求，可关联人 + 视频／会话；最近 10 分钟；同工具 UA，排除合法工具调用 | 单事件工具 UA 命中 | 至少 2 类请求阶段出现工具 UA，工具请求数 ≥ 20 | 至少 3 类请求阶段出现工具 UA，工具请求数 ≥ 100 |

R6：coverage 为成功访问唯一分片数/清单总片数；monotonic 为有效相邻请求对中序号递增的比例；CV 为请求间隔标准差/均值。区分清晰度和轨道，保留实际重试，去除采集重复。均值为 0 或样本不足时，CV 不可判断。

### 4.3 R9 异常时段活跃

沿用“单事件辅助标签”：按租户业务时区，事件落入预定义低活跃时段就标记 is_off_hours=true。[02:00, 06:00) 仍是候选时段，不表示业务禁止访问。标签为 0 分，不设置三档，也不因请求多而重复加分。

可按人聚合夜间请求数、活跃分钟数、视频数、夜间占比和历史偏离，或作为 R2、R8 的解释维度。本稿不额外新增一个与现有规则重复计分的夜间高活跃规则。

## 5. 哪些异常可以进入盗版嫌疑分

异常分可保留全部适用规则。嫌疑分需逐项检查方向、主体和上下文；不能把异常总分直接改名为盗版嫌疑分。

| 规则证据 | 嫌疑方向与准入条件 | 不应作出的推断 |
| --- | --- | --- |
| R1 必要授权步骤缺失且内容访问获准 | 主要证据：授权绕过/异常获取线索；要求链路完整、缓存等已排除 | 一般顺序异常不等于绕过；获准访问不等于已传输 |
| R2 高速拉片 | 主要证据：异常获取线索；排除允许的下载/预取，并区分鉴权与实际传输 | 不能直接认定已经解密、录制或传播 |
| R3 不允许的多视频并发 | 主要证据：共享或自动化使用线索；要求可靠的活跃区间与主体归因 | 不能把视频切换次数当作并发 |
| R4A 范围外复用尝试/成功 | 主要证据：盗版尝试；成功时进一步支持异常访问/获取 | 失败的批量尝试不证明内容已经泄漏 |
| R4B 同 token 多环境使用 | 主要证据：凭证共享/泄漏，作为盗版尝试线索；符合高档即可单独进入高危险 | 不证明 token 绑定者就是实际操作人，也不证明内容已流出 |
| R5 环境变化、R6 机械访问、R8 长时访问、R10 工具特征 | 辅助证据：需要与已准入主要证据处于同一活动上下文，才进入嫌疑分；不能仅因同账号在 24 小时内都出现就关联 | 单独出现只体现异常，不单独建立主体盗版嫌疑分 |
| R7 视频失败量与失败率高 | 本版仅进入访问异常分；可辅助排查故障、定位探测来源。若定位到范围外批量复用，则按 R4A 计对应嫌疑事实 | 不能从失败率直接推断盗版；与 R4A 同一事实不重复计分 |
| R9 夜间标签 | 0 分上下文 | 夜间本身不代表盗版 |

即使使用相同原始请求，速度、分片顺序、工具 UA 也可能是不同特征；它们可以互补。相反，同一个速度事实被多个阈值或多个版本规则命中，仍是同一事实。

## 6. 计分去重、限额加分与跨时段反复

### 6.1 计算顺序

```text
原始事件 → 特征 → 规则最高档 → 异常事实
          → 主体/嫌疑方向/上下文检查 → 可计入嫌疑的事实
          → 同事实去重 → 分组限额加分 → 反复异常加分
          → 主体分数、等级、证据状态
```

以各规则的 5/10/30/60 分钟或 24 小时窗口检测事实，每分钟评估一次。主体采用最近 24 小时的事件时间范围形成画像；不把每分钟的历史总分再相加。新增迟到日志修正相应事实和历史分数，只有事实仍在当前 24 小时范围内时才影响当前画像。

### 6.2 同事实与不同特征

| 情况 | 处理 |
| --- | --- |
| 同一事件被重复采集 | 去除采集重复 |
| 同一速度同时命中 >5、>10 或新旧规则版本 | 同一特征、同一活动事实，只取最高档 |
| 同一次异常被重叠滑动窗口重复命中 | 合并为同一异常片段，更新档位，不加出现次数 |
| 同一片段同时高速、机械、使用工具 UA | 可作为不同特征限额加分；不能把速度本身再包装成工具证据 |
| 同 token 环境复用同时触发 R4B 和相同环境事实的 R5 | 同一环境事实取最高分；不把 50 与 15 相加 |
| 同一规则命中多个视频或多 token | 主体上保留该规则/特征最高分，不逐个相加；数量类特征在规则内计算 |

保留事实的特征类型、原生主体、视频/会话范围、事件时间段、日志引用和规则版本，说明每项分数的来源。同事实去重不能只按原始事件 ID：共享日志不必然代表同一特征。

### 6.3 证据组与上限

| 证据组 | 主要证据 | 可补充的独立辅助特征 | 分组上限 |
| --- | --- | --- | ---: |
| G1 授权保护 | R1、R4A | 本版不新增 | 60 |
| G2 内容拉取 | R2 | R6、R8 | 60 |
| G3 多路/多环境使用 | R3、R4B | R5；与 R4B 同环境事实时去重 | 60 |
| G4 客户端 | 无独立主要规则 | R10 | 15 |
| G5 访问故障/失败 | R7 | 本版不新增 | 50，仅用于异常分 |

同一主体先对同事实取最高分，再对每个规则子项/特征取最近 24 小时的最高分；不同特征在组内相加后封顶。50 分主要证据可以被辅助证据补充至 60 分，但不能在同类行为中无限堆分。

嫌疑分中的辅助特征须有相关主要嫌疑证据佐证。缺少相关主要证据时，辅助特征仍可计入异常分，暂不进入嫌疑分。跨主体不复制总分，只传递可归属的原始事实，再重做准入和去重。

### 6.4 反复异常加分 B

“重复发生”指不同时间段内新出现的异常片段，而不是同一事件重新入库、同一片段被再次计算，或同一持续行为刚好跨过一个固定窗口边界。

候选判定：同一主体、同一主要证据类型；原始支撑事件不重复，片段时间不重叠，且两次片段之间至少 30 分钟没有新的该类异常证据。数据延迟、采集断档或采样空白不能被当作行为已经停止；缺少足以判断片段分离的记录时不启用反复加分。持续一整夜的同一次拉片仍为一个片段，其持续性由 R8 等特征表达。

| 最近 24 小时独立片段数 n | 反复异常加分 |
| --- | ---: |
| 0～1 | 0 |
| 2 | 5 |
| 3 | 10 |
| ≥4 | 15 |

对每种主要证据类型分别统计片段数，取最多的一类计算 B；全主体最多加 15 分，不将多个类型的加分再次累加。异常分可包含反复 R7；嫌疑分只统计已准入的主要嫌疑证据。R8 的 24 小时滚动命中和辅助规则命中不再单独制造反复加分。

这一版从 v0.1 的“规则短窗口结束即退出当前总分”，调整为“主体最近 24 小时画像”。片段超过 24 小时后退出当前计算，历史最高分和已冻结证据继续保留，不逐日永久累加。

## 7. 总分公式、主体适用范围与等级

### 7.1 通用公式

令 A1～A5 为全部正确归属的异常事实在各证据组去重、取特征最高档、限额相加后的分数；令 S1～S4 为通过第 5 节检查的嫌疑事实对应分组分数。

```text
异常分 A = min(100, A1 + A2 + A3 + A4 + A5 + B_异常)

盗版嫌疑分 S = min(100, S1 + S2 + S3 + S4 + B_嫌疑)
```

S 没有 R7 所在的 G5。每个准入事实使用原有规则异常档位的分值，不再额外乘一个未经校准的“盗版概率权重”。仅靠辅助特征没有相应主要嫌疑事实时，S 没有可计分贡献；必要数据无法判断时保留数据不足，而非宣称未发现风险。

### 7.2 按主体使用哪些证据

| 证据 | 个人行为嫌疑 | 视频盗版嫌疑 | token 使用嫌疑 |
| --- | --- | --- | --- |
| R1 | 可归因到该个人的链路事实 | 仅归属对应视频的链路事实 | 本版不自动投射 |
| R2 | 按该个人跨视频计算 | 必须在该视频局部重算，不能复制跨视频倍率 | 本版不自动投射 |
| R3 | 可归因到该个人的并发事实 | 不因“此人并发很多视频”直接给每个视频加分 | 不自动投射 |
| R4A | 只有实际请求者/账号活动可归因时进入；仅 token 绑定者另列关联凭证风险 | 高档只归属具体越权成功的目标视频；低中档跨视频尝试先展示线索，不把 token 分数逐一投射到视频 | 原生主体，直接判断 |
| R4B | 可归因到该账号活动时使用；只有 token 自带观众 ID 时，先列关联凭证风险 | 多环境共同涉及的视频按局部环境/跨度/请求门槛重算；或关联 token 强绑定的唯一视频，明确是凭证暴露方向；账号级 token 不给所有授权视频批量加分 | 原生主体，直接判断 |
| R5 | 与主要证据相关的个人环境变化 | 不把全体观众的不同 IP/UA 汇总成某视频的异常设备数 | 不重复建立与 R4B 相同的环境证据 |
| R6 | 对应个人访问片段 | 对应视频具体访问片段，不能把多个正常观众拼成一次机械访问 | 本版不自动投射 |
| R8 | 对应个人的长时访问 | 不直接投射全人 24 小时时长 | 不直接投射 |
| R10 | 相关个人/会话工具特征 | 与该视频主要嫌疑事实相关的同一活动特征 | 与该 token 主要嫌疑事实相关的工具特征 |
| R7 / R9 | R7 不继承，R9 为标签 | R7 仅异常分，R9 为标签 | 不直接投射 |

即使主要规则达到 50 分，主体映射也必须成立。token 的高危险不等于其绑定者本人的盗版行为嫌疑高危险；视频凭证暴露的高危险，也不等于内容已被下载或传播。

R2 当前 C ≥ 1,800 秒的候选门槛对短视频局部分析覆盖不足；本版明确保留该限制，不用个人跨视频总量替代。短视频局部速度需要独立校准窗口和最低内容量，现阶段可以先展示已有局部特征，不强行给出 R2 分数。

R4A 低中档使用“同 token 涉及多个视频”的计数口径，不能直接等同于每个目标视频的尝试严重程度。本版保留视频侧具体尝试事件和来源，视频局部的尝试分档需单独校准；R4A 高档中已观察到的具体越权成功事实则可直接归属到目标视频。

### 7.3 分数等级

异常分与嫌疑分使用同一展示区间，但含义分别标明；100 分不是 100% 盗版概率。

| 分数 | 异常等级 | 盗版嫌疑等级 |
| --- | --- | --- |
| 0 | 无可计分异常命中 | 无可计分嫌疑证据；仍可能有辅助线索 |
| 1～24 | 一般 | 一般 |
| 25～49 | 注意 | 注意 |
| 50～100 | 高危险 | 高危险 |
| — | 数据不足/不可归因 | 数据不足/身份待核实 |

一项符合准入与归因条件的主要规则达到 50 分，即可将相应主体定为高危险。多个不同特征、独立时间段可进一步提高分数，但不依靠重复计算凑分。

## 8. 严重程度、证据状态和人工复核分开

| 证据状态 | 含义 | 允许的输出 |
| --- | --- | --- |
| 初判 | 特征有可用的估算/推断口径，但仍有明确假设或待补日志 | 可显示高危险初判；列出估算方法和待核实项 |
| 特征已核实 | 计分所引用特征已被对应可信数据核实，语义、时间和关联满足条件 | 可显示高危险／特征已核实；不等于盗版已确认 |
| 数据不足 | 缺少判断所必需的日志、授权范围、主体关系或特征口径 | 相关规则不可判断；已有可算项可保留分数并列出缺失规则，无可算依据时显示“—” |

主体分数引用的任一贡献项仍是估算，则整体保留初判状态；全部贡献项已核实时标记“引用特征已核实”，同时仍展示没有覆盖的规则。人工审核是否完成另设状态，不能用“已复核”替代日志完整性，也不能用“特征已核实”代替人工认定。

采样处理：

- 对于 R4B，只要样本已经直接记录同 token 在多个明显不同环境交错使用并达到该档门槛，这些“已经看到的使用事实”不会因采样而消失。可就这一事实核实，不声称看到了所有请求。
- 对于 R2，样本请求数 × 10 秒 / 采样率估计的是含重试的请求内容量，不是去重媒体时长 C。不能直接套用本稿的全量 C 阈值。若后续独立校准了样本口径、误差与重试处理，可以作为初判规则；未校准前只展示线索，不能虚构对应分数。
- 对于 R3，只有请求样本时不能把首末请求之间全视为活跃。需要独立校准请求活跃区间，或增加可信心跳，才可形成可计分初判。
- 对于 R6/R8，准确覆盖率、间隔规律、完整活跃分钟数与去重 C 依赖全量或等效完整数据；当前样本不支持时记为不可判断。
- 对于 R7，采样分子分母须同口径，不能照搬全量示例阈值。CDN 全量日志是否包含同类鉴权失败、具体结果含义是什么，需要先确认。
- 不再统一把“初判”封顶 25 分；前提是该初判口径确实可计算且经过相应校准。取消封顶不等于为缺少特征的规则授分。

建议展示：主体、A/异常等级、S/嫌疑等级、嫌疑方向、证据状态、身份依据、人工复核状态、主要贡献事实和缺失项。

| 场景 | 分数计算 | 输出解释 |
| --- | --- | --- |

| 已归因个人 10 分钟请求 4,800 秒去重内容，机械高档、工具一般档 | R2=25，R6=15，G2=40；R10=5 | A=45，S=45／注意；相关辅助事实补充分数，不再只取 R2 的 25 分 |

## 10. 回放与下一轮校准重点

这一版已经确定计分结构，尚未确认生产数值。应先验证以下问题：

1. R4B 的环境分类、交错跨度、每环境请求门槛，能否排除正常换网、客户端切换和合法多端使用；token 绑定/续期规则在各终端是否一致。
2. R1 必要链路、授权有效期回溯和日志覆盖是否足以判断“没有发生”；R4A 是否有可靠的历史授权范围和结果语义。
3. 10/25/50 与 5/10/15、分组 60 分上限、反复异常 5/10/15 分、50 分高危险阈值的命中与误报分布。
4. 主体最近 24 小时画像、片段至少间隔 30 分钟的候选口径，是否会把同一持续行为错误切分，或掩盖跨时段反复出现。
5. 视频局部证据与个人跨视频证据能否准确分离，token 绑定者与实际请求者能否区分；短视频 R2 口径和缺失数据单独记录。
6. 采样初判与完整日志复核间的升降级，以及故障、合法工具、夜间学习等正常场景是否被错误转化为盗版嫌疑。

验证时分别统计异常规则命中情况与主体嫌疑的人工复核结果；只有积累可靠标注并验证校准关系后，才讨论将分数解释为概率。
