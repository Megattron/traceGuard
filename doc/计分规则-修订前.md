# 主要计分规则

> 说明：风险分不是由单一行为决定，而是系统从多个维度综合评估。分数越高，代表异常行为越集中、证据越强，越需要审核人员介入复核或处置，风险分本身代表的是“异常行为的综合程度”，不是某一次播放是否“实锤”的直接结论。

补充维度说明：

- **是否可通过单事件判断**：指仅凭一条事件及必要的解析、参考信息能否判断规则命中，无需关联其他事件或历史统计；单事件可提取的信号不等于完整规则可由单事件判断。
- **判断主体**：指规则关联、聚合并作出判断的对象。“人”指观众或个人账号，不将包含多个观众的客户/租户账号直接视为一个人；“人 + 视频”指某人对某视频的访问，不是汇总该视频全部观众的行为。“视频”聚合以同一租户下的同一视频为范围；“视频访问事件”则表示可由单事件判断并归属到视频，不要求先汇总该视频的全部请求。
- 授权异常复用以 **token** 为直接主体；脚本或工具的静态特征以**单次请求**为判断对象，识别到人或视频时再归属风险。
- “静态”指可由单事件判断，不表示字段永远不变；规则主体也不等于最终处置对象。

| 规则类型 | 解释 | 风险含义 | 是否可通过单事件判断 | 判断主体 |
| --- | --- | --- | --- | --- |
| 授权链路异常 | 正常播放通常会按“获取授权、获取播放地址、获取密钥、播放视频片段”的顺序发生。如果中间步骤缺失、顺序异常或间隔异常，会增加风险分。 | 可能存在绕过正常播放器流程、重放授权或异常调用接口的行为。 | 否，需要关联多步骤事件并检查缺失、顺序及间隔。 | 人 + 视频（同一播放会话） |
| 播放速度异常 | 一个观众或账号在较短时间内访问了大量视频内容，明显超过正常观看速度。 | 可能不是人在正常观看，而是工具在批量下载视频片段。 | 否，需要统计时间窗口内的内容请求量与观察时长。 | 人；单视频检测时按人 + 视频统计 |
| 同时多视频播放 | 同一观众或账号在同一时间段内访问多个视频。 | 可能存在账号共享、多人同时使用，或脚本批量拉取内容。 | 否，需要关联同一主体访问不同视频的活跃时间段。 | 人（跨视频） |
| 授权异常复用 | 同一个授权凭证被用于多个视频、多个环境或多个访问来源。 | 可能存在授权泄露、token 被复制、脚本复用授权等风险。 | 否，需要比较同一 token 的多次使用记录；单次访问是否超出授权范围属于另一个判断。 | 授权凭证 token（关联人、视频与环境） |
| 设备与网络环境频繁变化 | 同一观众短时间内出现过多设备、浏览器、网络或地区变化。 | 可能存在账号共享、代理访问、自动化工具访问等情况。 | 否，需要比较一段时间内的设备或网络环境记录。 | 人（跨视频） |
| 视频片段访问过于规律 | 视频片段访问行为非常机械，例如持续、连续、规律地访问，缺少正常观看中的暂停、拖动、回看、退出等行为。 | 可能是下载工具按顺序抓取视频片段。 | 否，需要分析一组分片请求的顺序、间隔及覆盖情况。 | 人 + 视频（同一播放会话） |
| 视频失败请求过多 | 同一视频在时间窗口内，明确失败的请求数与失败率同时达到阈值，并满足最小样本量要求；先按同一种请求阶段统计。 | 可能存在探测、异常重试或鉴权/配置故障；需按人、token、IP 进一步归因，不能直接将风险归给所有观众。 | 否，需要按视频聚合窗口内的请求量、失败量和失败率。 | 视频（同一租户下的同一视频） |
| 长时间高强度观看 | 观众或账号在较长时间内持续访问大量视频，几乎没有正常休息间隔。 | 可能不是正常人类观看行为，存在自动化访问或批量学习/下载嫌疑。 | 否，需要聚合较长时间内的访问量、活跃时长及空闲间隔。 | 人（跨视频） |
| 异常时段活跃 | 可归属到视频的单条访问事件，发生在预先定义的凌晨等低活跃时段，即标记为异常时段活跃；成功和失败请求均可标记，后续分别统计。 | 仅为辅助信号，不代表违反视频开放时间或存在盗版行为；标签不独立累计风险分，供后续按人聚合分析。 | 是，依据事件时间、业务时区及预先定义的时段即可判断；不依赖即时历史聚合。 | 视频访问事件（归属视频；识别到观众时可进一步按人聚合） |
| 脚本或工具特征 | 访问行为中出现明显非正常播放器特征，例如自动化工具、下载器或异常客户端特征。 | 可能存在技术工具批量访问或下载视频。 | 部分可以。UA、请求头等工具特征可单事件匹配；高频请求、机械拉片等行为特征需要多事件。 | 单次请求（可归属到人、视频）；行为特征按人或人 + 视频统计 |

## 规则补充定义

### 视频失败请求过多

先发现视频侧访问异常，再分析来源。首版以 TS 鉴权请求为例；授权、密钥和分片请求应分开统计，不混用不同阶段的次数及成功/失败语义。

| 项目 | 定义 |
| --- | --- |
| 聚合主体 | 同一租户下的同一视频 |
| 时间窗口 | 最近 10 分钟，每分钟计算一次；以事件发生时间统计 |
| 总请求数 N | 窗口内同一请求阶段、具有明确鉴权结果的请求数；仅去除采集重复，保留实际发生的重试 |
| 失败请求数 F | N 中明确鉴权失败的请求数；TS 样例对应 tsReqResult=false |
| 失败率 R | F / N；N=0 时不判定 |
| 命中条件 | N ≥ 最小样本量，且 F ≥ 失败量阈值，且 R ≥ 失败率阈值 |

缺失或未知结果单独记录，不直接当作失败。现有 TS 鉴权结果仅能区分通过与未通过；过期、越权、内容不存在等原因需相应错误码或其他日志支持。无法归属到具体视频的请求不强行计入某个视频。

以下仅为全量日志口径的历史回放候选，不是已确认的生产阈值：最近 10 分钟 N ≥ 100、F ≥ 30、R ≥ 20%，三项同时满足才命中。

| 示例 | 是否命中候选条件 | 原因 |
| --- | --- | --- |
| 2 次请求、2 次失败 | 否 | 样本不足 |
| 1,000 次请求、40 次失败 | 否 | 失败率为 4%，未达到阈值 |
| 200 次请求、50 次失败 | 是 | 失败量与失败率均达到阈值，且满足最小样本量 |

采样数据必须记录来源、采样率和采样方式，在同一口径下计算分子、分母并校准阈值；不能将样本数直接当作全量数，也不能未经验证就套用上述数字。准实时 TS 日志为 1/10 采样，次日 CDN 全量日志需在确认结果字段语义一致后用于复核。

命中后按观众、token、IP 拆分失败量和失败率：集中在少数来源时检查重试、探测等行为；分散在大量观众时优先排查服务或视频配置故障。视频侧异常不能直接转化为对全部观众的个人风险判断。

本规则捕捉“失败量大且失败占比高”。热门视频中失败率不高但失败量突然上升的情况，可后续独立定义“失败量突增”，与该视频历史同类时段比较，本轮不合并进该规则。

### 异常时段活跃：单事件辅助标签

原“异常时段高活跃”调整为“异常时段活跃”。这里的异常时段指凌晨等通常低活跃的时段，不是业务明确禁止访问的时间；单事件实际确认的是“该时段发生了访问”。

判定方式：事件可归属到视频，且事件发生时间按租户业务时区转换后落入预先定义的低活跃时段，则 is_off_hours=true。可将 [02:00, 06:00) 作为历史验证的候选时段，不作为已确认的生产配置。

使用预先定义的时段时可以单事件判断；如果改为即时判断“是否偏离该视频的历史活跃情况”，则需要历史统计，不再是纯单事件规则。

事件至少保留 video_id、可识别时的 viewer_id、event_time、event_type、请求结果、is_off_hours、业务时区及所使用的时段定义版本。观众未知时保持未知，不由视频或租户账号代替个人身份。

成功、失败请求均可带标签，但后续分别统计“夜间失败尝试”和“夜间成功内容访问”。TS 鉴权通过不等于分片已完整传输，更不等于实际观看。

标签本身不独立累计风险分，避免一次正常播放产生大量分片请求而反复加分；标签供后续聚合规则引用，也可按视频汇总展示夜间访问情况。

### 后续按人聚合的夜间行为特征

按同一租户内的观众或个人账号跨视频聚合；客户/租户账号不直接视为一个人。只纳入夜间事件可计算夜间行为，计算占比和历史偏离还需要对应的全部事件及历史数据。

| 特征 | 提取口径 | 分析含义 |
| --- | --- | --- |
| 夜间请求数 | 统计窗口内 is_off_hours=true 的请求数；按请求阶段、成功/失败分别统计 | 夜间访问规模 |
| 夜间访问视频数 | 夜间成功内容访问关联的不同 video_id 数 | 是否跨多个视频访问 |
| 夜间活跃分钟数 | 按业务时区划分分钟桶，每个出现成功内容访问的分钟记为活跃，再累计活跃分钟数 | 夜间访问持续性；属于网络访问活跃，不等于实际观看 |
| 夜间最长连续活跃段 | 统计相邻且连续活跃的分钟桶形成的最长时间段；无事件分钟会中断该统计段 | 持续访问程度；采样缺失可能使统计段缩短，不能据此证明用户休息 |
| 夜间访问占比 | 同一统计周期、同一请求阶段及结果口径下，夜间请求数 / 全部请求数；需设置最小样本量 | 访问是否主要集中在夜间 |
| 夜间拉片速度 | 夜间观察窗口内的请求内容量 / 观察时长；采样估算与全量结果分别标记 | 是否同时存在高速拉片；不等同于播放速度 |
| 夜间习惯偏离 | 将本次夜间访问与该观众历史可比时段的行为比较 | 是否突然改变访问习惯；历史不足时不作确定判断 |

若后续新增人维度的“异常时段高活跃”聚合规则，可定义为：夜间观察窗口内，活跃分钟数达到持续性阈值，且内容访问量或请求密度达到强度阈值。活跃分钟数衡量持续性，内容量或请求密度衡量强度；本轮不设定生产阈值，需通过历史回放校准。

该人维度聚合规则属于后续规则设计，不作为本次新增的已启用计分规则。实际计分时应按聚合窗口输出命中，并处理与高速拉片、长时间高强度观看等规则的重复计分。
