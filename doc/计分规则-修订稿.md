# 计分规则与基础特征提取设计

修订日期：2026-10-22。本文以既有 10 类规则为入口，补充从原始日志到可计算特征的定义。特征层提供事实、计算口径和证据质量，规则层决定是否异常，计分卡层决定分值、等级及主体嫌疑。

## 1. 审查结论与设计边界

原版本可以视为“规则导向的特征需求清单”，还不是完整的基础特征提取规格。主要缺口是：统一事件字段和结果语义不完整，主体关联依据不明确，窗口和分母未统一，采样与全量指标混用，以及缺少不可计算/缺失数据的输出约定。本次补齐这些内容。

```text
原始日志 → 标准事件 → 单事件解析/标签 → 主体与窗口聚合特征
         → 规则命中及异常事实 → 计分卡的异常分/嫌疑分
```

**基础特征不预先写死风险结论。** 例如先输出失败数、失败率、样本量，而不是只输出“失败过多=true”；先输出 token 环境数、交错跨度及每环境记录数，再由规则判断一般、注意或高危险。

本文件负责字段和特征口径；计分档位及总分算法以 [计分卡 v0.2](/Users/jeremyhong/cc_workspace/polyv-develop/tasks/20261022_TraceGuard/doc/计分卡-v0.2.md) 为准。本文的统计窗口和示例阈值仍为设计候选，不代表生产数据已验证。提取层增加更细的证据质量说明，不自动修改计分卡的数值。

### 1.1 四个层次

| 层次 | 例子 | 是否单事件可得 |
| --- | --- | --- |
| 原始事实 | 请求时间、token、UA、鉴权结果 | 已有字段可直接读取 |
| 单事件派生特征 | 客户端类别、URL 分片定位、是否低活跃时段、是否超出已知授权范围 | 可以，但可能依赖解析规则或当时有效的参考数据 |
| 聚合特征 | 失败率、唯一分片数、环境数、访问顺序比例 | 需要多事件和时间窗口 |
| 规则与嫌疑结论 | 失败过多、机械访问、共享/泄漏嫌疑 | 组合特征、数据前提及规则阈值后判断 |

“静态”只表示单事件可计算，不表示字段永远不变。单事件中存在一个信号，也不意味着完整规则可由该事件判断。

## 2. 已知数据与能力边界

依据同目录的 `20260518/background.md`、日志样例及原型。实际检查到的 TS 样例文件仅含 2 条可解析记录，7 个字段齐全，两个结果均为布尔 false；这只验证样例结构，不代表生产分布或全链路覆盖。

| 来源／标准事件类型 | 已知原始字段 | 可确认的事实 | 当前不能直接确认 |
| --- | --- | --- | --- |
| 后台授权日志／request_hls_token | user_id、viewer_id、video_id、token、request_at、client_ip | 日志记录的授权请求/凭证关联信息 | token 当时真实授权范围、历次续期有效期、详细失败原因；样例没有这些字段 |
| 播放地址日志／request_m3u8 | 上述主体字段、play_id、user_agent、response | 对应 HTTP 请求及状态 | 客户端实际使用了地址；play_id 并非全终端具备 |
| 密钥日志／request_key | 主体字段、play_id、user_agent、response | 对应密钥 HTTP 请求及状态 | 客户端实际持有/使用密钥，或已完成解密 |
| TS 鉴权日志／request_ts | tsReqTime、tsReqUrl、tsReqTk、tsReqIp、tsUa、tsReqResult、tkVrid | 鉴权事件及准许/拒绝结果；文档称 1/10 采样 | 实际响应字节、完整传输、实际观看、具体拒绝原因、稳定设备 ID |
| CDN 次日日志／cdn_ts_access | 需核实真实字段与结果语义 | 按厂商提供内容确认 HTTP 访问/传输观测 | 是否包含所有鉴权失败、能否与鉴权事件一一对应、是否有响应字节/Range/中断信息 |
| 视频元数据与媒体播放列表 | 可按视频关联时长；m3u8 可解析分片清单 | 经映射核实后的媒体时长与分片位置 | 不能把所有 URL 中间后缀都直接当成视频 ID 或清晰度 |

**现状约束：** 没有全链路会话 ID；token 可以合法续期复用；TS 无完整 play_id；不同服务看到的 IP 可能不同。暂停、拖动、退出、播放速度、稳定设备标识和可信播放状态心跳均未在已知事件中提供。

## 3. 标准事件约定

### 3.1 通用字段

下面是目标标准事件，不表示原始日志已包含全部字段。缺失保留 null 和原因，不伪造默认值。

| 标准字段 | 来源或生成方式 | 约束 |
| --- | --- | --- |
| event_id、source_record_ref | 原生事件 ID 优先；否则使用来源实例 + 文件唯一标识 + 记录偏移等稳定采集位置 | 同一日志重放保持不变；不能只用 token+URL+毫秒时间生成 ID，真实同时请求可能碰撞 |
| request_ref | 服务端请求/链路 ID，有则保留 | 没有就为空；跨来源没有共同 ID 时不假装是一一对应请求 |
| event_type、source、schema_version | 按来源配置生成 | 不将鉴权事件与 CDN 传输记录当成同一种事件 |
| event_time、ingest_time | 请求发生时间与采集时间分别保存 | 内部统一时间表示；保留原始精度、来源时区和解析版本 |
| tenant_id、tenant_source | 后台已核实的租户字段，或视频/授权记录关联 | user_id 的业务含义先核实；不能默认它是个人账号，也不能仅靠 URL 前缀确认租户 |
| viewer_id、identity_basis | 业务确认的观众映射及依据 | 与 token 绑定观众分开；仅声明/绑定身份不能升格为实际访问者 |
| credential_viewer_id | tkVrid 或授权记录中的 token 绑定观众 | 可用于凭证归属，不证明实际发起人；缺失不填空字符串 |
| video_id、video_id_raw、video_mapping_status | 保留原值，通过媒体资源映射确认标准 ID | 只有候选解析结果时标为 CANDIDATE，不能用于跨租户强关联 |
| token_ref | 同一规范下的稳定 token 指纹/内部索引 | 跨来源使用相同关联规范并保留版本；分析输出不暴露完整 token，原始证据按权限引用 |
| play_id | 原样保留 | 不是全局唯一身份；需结合租户、token、视频及时间判断 |
| client_ip、ip_basis | 可信日志字段及来源说明 | 保留 IPv4/IPv6；来源未确认时降低关联可信度，不直接信任客户端自报转发头 |
| ua_raw、ua_family、os_family、sdk_family | 原始 UA 与版本化解析结果 | SDK 小版本变化不当作设备变化；未知类别单独统计，不把所有未知当成同一客户端 |
| auth_result | PASS / FAIL / UNKNOWN | 仅由明确鉴权结果得到；缺失不当 FAIL；与 HTTP 状态分开 |
| http_status、delivery_status、failure_reason | 原始状态码、经来源确认的传输结果、业务错误码 | 200 不自动证明业务授权成功或内容完整传输；failure_reason 无字段则 UNKNOWN |
| object_path、resource_version、playlist_ref、rendition_ref、track_type | 资源路径及播放列表映射 | 分析层保留资源身份，不因去掉签名参数而合并不同媒体资源 |
| segment_index、media_start_s、media_end_s、segment_duration_s | 经清单核实的分片位置和时长 | 序号不是媒体秒数；音视频分离时不能把同一时间段重复计算两遍 |
| sampling_rate、sampling_method、sampling_unit | 来源采样配置 | 采样单位是鉴权调用、请求、分片还是会话必须明确；未知方式保留 UNKNOWN |
| raw_log_ref、parse_status、quality_flags | 原始位置和处理结果 | 每个聚合结果能够追溯；解析失败事件保留，不直接丢弃 |

### 3.2 TS 字段的实际映射

| 原始字段 | 标准字段 | 提取方式 |
| --- | --- | --- |
| tsReqTime | event_time | 按该来源毫秒时间戳协议转换；同时检查时间范围，不用采集时间替代 |
| tsReqTk | token_ref | 生成稳定关联指纹；不从 token 后缀猜观众 ID |
| tsReqIp | client_ip | IP 解析与归一化，记录来源语义 |
| tsUa | ua_raw → 客户端/系统类别 | 使用版本化解析规则，保留原文和命中依据 |
| tsReqResult | auth_result | 已知样例为 JSON boolean：true→PASS，false→FAIL；其他类型按来源契约校验，不依赖字符串真值判断 |
| tkVrid | credential_viewer_id | 保留业务原值；若需解码，先确认编码契约及租户内身份映射，不擅自把可 Base64 解码的文本当统一 viewer_id |
| tsReqUrl | object_path → 视频候选/分片候选 → 媒体元数据关联 | URL 解析只给候选；经元数据/清单确认后填标准 video_id 和媒体区间 |

### 3.3 视频与媒体时间轴

1. 从 URL 提取路径、文件名、后缀和序号候选，保留解析器版本。对于形如 `<base>_3_0.pts` 的文件名，不仅凭样例认定 `_3` 的业务含义，也不直接把它删除后当作最终视频 ID。
2. 通过视频元数据、资源版本及实际媒体播放列表确认视频、轨道、清晰度和分片。Master Playlist 与 Media Playlist 分开处理。
3. 优先使用媒体清单的实际分片时长及时间轴；已知系统“10 秒/片”的说明可以作为经过业务确认的估算回退，并标为估算，不能掩盖末片或其他版本差异。
4. 同清单内可按分片身份去重；跨清晰度/轨道按同一内容的媒体区间求并集。不同内容版本若尚未确认共用同一时间轴，先分别计算，不强行合并。不能假定不同清单里相同序号代表同一媒体位置。HLS 的分片时长和跨清单序号限制见 [RFC 8216 §4.3.2.1、§6.3.2](https://www.rfc-editor.org/rfc/rfc8216.html)。
5. 分片清单缺失时，可以保留观测请求数和序号候选；总片数、准确覆盖率、准确媒体秒数按依赖情况返回不可计算，而不是用 max(segment_index)+1 代替总片数。

## 4. 主体关联与会话关联

### 4.1 主体键

| 主体 | 聚合键及使用边界 |
| --- | --- |
| 观众/个人账号 | tenant_id + 业务核实的 viewer_id；同时保留 identity_basis |
| 凭证绑定观众 | tenant_id + credential_viewer_id；只用于凭证关联画像，不自动当作本人行为 |
| 视频 | tenant_id + 经确认的 video_id；需要时细分资源版本/轨道 |
| token | tenant_id + token_ref；租户未知时进入待关联范围，不与已知租户混算 |
| 环境 | 可信来源的 client_ip + ua_family/os_family/sdk_family 的归一化类别；同一比较口径下生成 env_ref |

IP 不是人的唯一标识，环境不是物理设备，token 不是会话。同一 NAT 下多人不能合并为一人，同一人换网也不能直接拆成人。

env_ref 至少需要可信 IP 和能够识别的客户端/系统类别；缺失时返回未知环境并另计数量，不用一个统一 UNKNOWN 值伪装成同一个已识别客户端，也不把两条未知 UA 视为强差异。

### 4.2 会话关联顺序

先用租户 + token + 视频缩小范围；有可靠 play_id 时再区分播放上下文。没有 play_id 时可按邻近授权/播放地址/密钥事件和候选 30 分钟空闲间隔形成推断会话。**不要把 play_id 或 IP 单独作为强关联键。**

如果同 token 同视频同时存在多个可能会话，而 TS 事件无法唯一归属：只纳入 token/视频级统计，标记会话关联歧义，不复制到每个候选会话，也不为追求完整链路强行挑一个。

输出 association_status=CONFIRMED / INFERRED / AMBIGUOUS / UNKNOWN 及关联依据。仅凭 IP+时间得到的关联至多作为候选；token 中的观众仍保持 credential_viewer_id。未来新增全链路 session_id 可替代推断，其价值在于原生保留关联关系，而不是事后猜测；可参考 [OWASP Logging：Interaction identifier](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html#event-attributes)。

## 5. 窗口、去重、采样与特征状态

### 5.1 时间与计数

- 窗口统一为事件时间半开区间 [T-W, T)，候选每分钟计算一次；1m/5m/10m/30m/1h/24h 各自输出，不能把分钟快照再相加当请求量。
- 原始事件先按稳定 event_id 去采集重放，真实重试保留。媒体覆盖再按媒体区间去重。这是两种不同去重，不能混用。
- 鉴权记录、CDN 访问记录分别统计。同一次实际请求可能在两边各有记录；没有可靠 request_ref 时不能相加成“总请求数”，也不能强行精确配对。
- 事件时间相同且没有可靠先后顺序时，不人为制造链路顺序；间隔可保留为 0，并记录时间精度。先后关系不确定的请求对不参与顺序比例，另外输出不确定对数。
- 允许迟到与源到齐条件按实际延迟分布设定，保留计算版本。迟到日志回补原事件窗口并更新结果，不把“今天入库”当“今天发生”。事件时间和迟到处理的概念可参考 [Apache Flink：Timely Stream Processing](https://nightlies.apache.org/flink/flink-docs-stable/docs/concepts/time/)。
- 来源处理进度已经越过窗口，并不能独自证明没有丢日志。判断“缺失步骤”还需来源覆盖、分区/文件齐备及无采集断档等依据；日后补到反证时允许修正历史结论。

### 5.2 采样约束

先确认“1/10”针对什么对象、成功失败是否同率、是否随机、是否只在部分缓存路径触发鉴权。若一次 CDN 请求不一定产生一次鉴权调用，鉴权样本不能直接代表全体 CDN 请求。

| 特征类型 | 样本可做什么 | 不能做什么 |
| --- | --- | --- |
| 事件数/鉴权失败数 | 输出观测计数；采样概率与单位已知且满足假设时另出估计值 | 未确认机制就统一乘 10 |
| 不同环境、不同视频、唯一分片数 | 输出已观察集合及总体数量下界 | 唯一集合基数直接乘 10 |
| 覆盖率 | 清单已知时输出观察到的覆盖下界 | 把没看到的片标为未请求，或把下界当准确比例 |
| 请求内容量 | 概率成立时估计请求等价秒数，保留重试影响 | 把它当作去重媒体时长或实际观看时长 |
| 顺序占比、间隔 CV、最长空闲 | 输出样本自身的指标和口径，供另行校准 | 视作完整请求序列的真实指标 |
| token 多环境已观察事实 | 已观察到的环境差异与反复使用可直接保留 | 由没观察到更多环境推断只有这些设备 |

对于单调的“至少达到”条件，可靠下界已经超过阈值时，可支持至少达到该档；未超过时不能反证总体未达到。例如样本已经观测到 2 个不同环境，则环境数至少为 2。失败率、CV、顺序比例不是这样可任意使用的数量下界。

### 5.3 每个特征的输出约定

| 字段 | 定义 |
| --- | --- |
| feature_code、feature_version | 稳定特征名及口径版本；与规则版本、计分卡版本分开 |
| subject_type、subject_key | 原生统计主体，保留身份依据和租户 |
| window_start、window_end、as_of_time | 事件时间范围及本次计算/补算时刻 |
| value、unit | 值与单位；不可计算时为 null，不填 0 |
| compute_status、reason_code | AVAILABLE / UNAVAILABLE；原因如 ZERO_DENOMINATOR、MISSING_MANIFEST、IDENTITY_AMBIGUOUS、SOURCE_NOT_READY |
| value_kind | EXACT、LOWER_BOUND、OBSERVED、ESTIMATED；说明值对目标总体的含义 |
| source、result_scope、sampling | 来源、鉴权/传输等结果层次和采样说明；不合并不兼容口径 |
| observed_event_count、eligible_count、unknown_count | 实际输入量、参与分母/计算的记录数和关键未知量 |
| association_status、quality_flags、evidence_refs | 关联质量、采集/时钟/映射等问题及可追溯的日志引用 |

完整覆盖且没有事件时，计数可以为 0；样本中没看到事件只能表示观测 0。分母为 0 的比率返回 null / ZERO_DENOMINATOR。缺 UA、缺清单、身份关联失败均不是对应行为没有发生。

### 5.4 先输出数据质量特征

| 特征 | 作用 |
| --- | --- |
| source_observed_record_count / parse_failure_count | 按来源记录收到多少原始记录、多少解析失败；不能只统计解析成功的记录 |
| video_mapping_success_ratio / identity_mapping_success_ratio | 以明确的可映射候选记录为分母，展示资源和身份映射覆盖，不把失败映射悄悄排除 |
| auth_unknown_ratio / unknown_ua_ratio | 以同来源同阶段观测事件为分母，展示关键字段未知占比 |
| ingest_delay_ms / source_gap_flag | 采集时间减事件时间及来源断档信息；负延迟需核查时钟，不按 0 隐藏 |
| manifest_mapping_ratio / window_source_coverage | 媒体区间映射覆盖和窗口来源覆盖证据；不能用该比例本身证明日志绝无丢失 |

这些质量指标用于决定业务特征是否可计算，不直接作为盗版分。解析失败而无法取得 event_time 的原始记录，质量监控按 ingest_time 统计，并明确分母范围，不混入事件时间的业务请求量。

## 6. 规则与特征总览

| 规则 | 基础特征 | 单事件能否判断完整规则 | 原生主体与边界 |
| --- | --- | --- | --- |
| R1 授权链路异常 | 必要步骤存在性、事件间隔、顺序违规、前置授权未观察到的通过分片数 | 否；缺失判断还依赖完整性和有效期回溯 | 人 + 视频／会话；歧义时退回 token/视频级，不强配人 |
| R2 拉片速度异常 | 请求数、请求等价秒数、去重授权媒体秒数、传输媒体秒数、各自速度比 | 否 | 人；视频局部单独重算，不复制个人跨视频倍率 |
| R3 同时多视频播放 | 窗口活跃视频数、请求活跃重叠代理、播放状态支持的并发数 | 否；这三项不能互换 | 人；缺少可信状态时只输出访问活跃代理 |
| R4 授权异常复用 | R4A 授权范围外尝试/通过；R4B 同 token 环境数、每环境通过数及交错特征 | 一次范围外访问可单事件检查；复用和多环境仍需聚合 | token；绑定观众不等于实际操作者 |
| R5 环境频繁变化 | IP/UA/环境数、切换次数与间隔、经补充的地区/运营商 | 否 | 人或凭证绑定观众分别统计，不能混成人的设备数 |
| R6 分片访问过于规律 | 覆盖率、递增比例、重复/回退数、间隔均值/标准差/CV | 否 | 人 + 视频／同一媒体分片序列，不汇总全视频所有观众制造机械行为 |
| R7 视频失败请求过多 | 明确结果样本量、失败数、失败率、未知量和失败来源集中度 | 否；单事件只能判明确失败 | 视频；仅表达访问异常，故障和盗版尝试后续归因 |
| R8 长时间高强度访问 | 活跃分钟、连续活跃段、请求间隔、去重内容量 | 否 | 人；网络访问不等于实际观看，也不能证明没有休息 |
| R9 异常时段活跃 | 单事件时段标签及后续夜间聚合 | 视频已归属、时区与时段已知时可以 | 视频访问事件；辅助标签 0 分，后续可按人聚合 |
| R10 脚本或工具特征 | 工具 UA 命中、解析类别、阶段覆盖、工具请求数 | UA 匹配可以；工具行为需要聚合 | 单事件或对应人/视频会话；与合法工具标签并存 |

## 7. 各规则的可实现提取口径

特征名为建议约定。实际身份或资源映射尚未确认时，先在 token/资源候选范围保留观察结果，不输出带确定个人/视频归因的特征。

### R1 授权链路异常

依赖标准授权、播放地址、密钥、TS 事件，及各终端所需链路、token/密钥有效期与来源覆盖。

| 特征 | 计算口径 | 关键限制 |
| --- | --- | --- |
| has_token_record / has_manifest_record / has_key_record | 对关联范围和有效回溯区间检查对应成功层次的事件；三值 true/false/unknown | 样例授权日志没有完整结果时只能确认记录出现，不能擅自认定签发成功 |
| token_to_manifest_ms / manifest_to_key_ms / key_to_ts_ms | 唯一或可信关联步骤的事件时间差 | 合法并行、终端顺序差异、时钟偏差需标记；非简单全局最早时间相减 |
| chain_order_violation_count | 按该终端协议配置检查顺序，统计可确定的违规请求对 | 无协议/时钟依据时不可计算，不使用固定流程通吃所有终端 |
| auth_pass_segment_without_prior_key_obs | 对每个通过分片检查此前有效 key 记录，统计未观察到前置 key 的分片 | 仅是未观察到；来源与回溯完整才可解释为必要步骤缺失 |
| chain_missing_required_step_count | 在链路必需性、完整性、缓存和有效期均已确认后统计缺失步骤 | 不能用单窗口 count(key)=0 直接得到绕过结论 |

R1 不把不同 IP 强行视为不同会话，也不把同 token 的合法多个 play_id 视作异常。

### R2 拉片速度异常

必须拆开“访问请求量”和“去重内容覆盖量”，并拆开“鉴权通过”和“传输观测”。

| 特征 | 计算口径 |
| --- | --- |
| ts_auth_pass_count_obs | 窗口内 request_ts 且 auth_result=PASS 的去采集重复记录数 |
| auth_request_equivalent_seconds_obs | 对每次通过事件累加其分片时长，保留真实重试；缺时长按依赖状态处理，业务确认的 10 秒回退需标估算 |
| auth_request_equivalent_seconds_est | 采样概率与单位适用时，按每条记录 duration / inclusion_probability 求和；它仍含重试，不是去重时长 |
| auth_unique_media_seconds_obs | 每视频内对通过事件对应的媒体区间求并集长度，再跨视频相加；样本结果为覆盖下界 |
| cdn_response_media_seconds_obs | 对符合所声明 HTTP 结果口径的 CDN 记录映射媒体区间求并集；只是响应观测覆盖 |
| fully_served_media_seconds | 仅当日志及对象/Range/中断等信息足以确认服务端完整输出分片，或有可靠字节到媒体时间映射支持完整区间时计算；不具备时返回 null；不能把部分响应字节比例线性折算为秒数，也不证明客户端已完整接收 |
| auth_unique_speed_ratio / cdn_response_speed_ratio | 各自的媒体秒数 / 窗口秒数；固定窗口分母，分别记录来源和结果层次，不混为统一“观看倍速” |

可同时提取 1m/5m/10m 口径供短视频验证；计分卡 v0.2 的 10m 与最低 1,800 秒仍是原候选，不把新窗口直接套进旧分档。视频局部必须只用该视频的内容量。

相同 10 秒媒体区间请求 3 次：请求等价秒数为 30，去重媒体秒数为 10。音轨与视频轨覆盖同一 10 秒，内容时长不变成 20。样本“76 次 × 100 秒”不能直接命名为观看时长。

### R3 同时多视频播放

| 特征 | 计算口径 | 当前可用性 |
| --- | --- | --- |
| window_active_video_count_obs | 同观众或同凭证观众在窗口内有内容访问的不同视频数，主体类别分别保留 | 标识/视频可映射时可提取；不等于并发 |
| request_active_interval_overlap_proxy | 按独立校准的请求活跃超时模型构造各视频区间，再计算重叠数量/时长 | 超时模型未校准时不提供确定值；首末请求凸包不能直接代表持续播放 |
| playback_state_concurrent_video_count | 依据具备时间、视频、播放状态及有效期限的可信状态事件计算区间重叠 | 现有日志未提供，当前不可计算；状态仍只证明报告的播放器状态，不证明人在观看 |

同一人在 5 分钟内依次访问 3 个视频，只能得到活跃视频数 3。即使有全量 CDN 日志，也不能自动将请求重叠解释为真实人类同时观看。

### R4A 授权范围异常与跨范围复用

依赖 token 在事件发生时有效的授权范围、有效期和续期历史。不能只查当前 token 状态回判历史。

| 特征 | 计算口径 |
| --- | --- |
| token_validity_at_event | VALID / EXPIRED / UNKNOWN；根据当时生效的签发/续期记录计算 |
| scope_relation | 对单事件目标视频检查 INSIDE / OUTSIDE / UNKNOWN；业务允许多视频就按真实范围判断 |
| token_video_count_obs | 窗口内同 token 实际访问过的不同视频数，只表示关联数量 |
| out_of_scope_attempt_count_obs / out_of_scope_video_count_obs | 仅 scope_relation=OUTSIDE 的事件数和目标视频数，分阶段统计 |
| out_of_scope_auth_pass_count_obs / out_of_scope_delivery_count_obs | 范围外且明确鉴权通过，或具有相应传输结果的记录数，分别保留 |

授权范围未知时，token_video_count_obs≥2 也不能直接认定越权。一次范围外访问可作为单事件特征；批量复用程度仍需窗口聚合。低中档跨视频计数不能直接复制成每个视频的局部严重程度。

### R4B 同 token 多环境使用

首版优先在同一 request_ts 来源、同一可信 IP/UA 口径中提取，避免把 SDK 客户端与服务端代理日志的不同 UA 当作真实环境漂移。

| 特征 | 计算口径 |
| --- | --- |
| token_env_count_obs / token_ip_count_obs / token_ua_class_count_obs | 10m 同 token 的不同环境、IP 和已识别 UA 类别数；样本下是总体下界 |
| token_env_event_count / token_env_auth_pass_count | 按环境统计全部观测量及明确通过量，计数不因采样先乘 10 |
| token_env_first_ts / token_env_last_ts | 每环境首末观测时间，只是观测跨度，不是连续在线时间 |
| env_observed_span_overlap_s | 环境对 A/B 的 max(0, min(last_A,last_B)-max(first_A,first_B))，单位秒 |
| env_switch_count / interleaved_env_pair_count | 按可确定的事件时间顺序统计环境切换和实际出现交错序列的环境对；时间相同的顺序不确定事件不虚构交错 |
| declared_client_difference | 按版本化客户端类别规则标记是否明显不同；未知 UA 不视为强环境差异 |

首末区间重叠只是代理特征。规则需一起检查每环境实际通过记录数、实际交错序列及跨度，不能由区间凸包独自推出反复同时使用。iOS/Android 等表述是不同声明客户端环境，不是已确认的两台物理设备。

如果 token 只强绑定一个视频，可将凭证暴露关联到该视频；否则视频侧需要按实际目标视频重算这些局部环境特征，不把账号级 token 所有可访问视频批量标高风险。仅凭 credential_viewer_id 不能把复用归给本人。

### R5 设备与网络环境变化

| 特征 | 计算口径 |
| --- | --- |
| subject_ip_count_obs / ua_class_count_obs / env_count_obs | 1h 内按同一种身份依据聚合，未知客户端单列 unknown_ua_count |
| env_transition_count / env_transition_gap_ms | 同一比较口径下可确定顺序的相邻事件，环境变化次数及切换间隔 |
| region_count_obs / isp_count_obs | 可信 client_ip 关联带版本/时点的 IP 数据后去重；未查询不算“没有变化” |

保留切换的类别和上下文，区分同客户端换 IP 与客户端类别改变。已有字段不能得到稳定设备数，不输出名为真实 device_count 的指标。IP 地区不能充当精确地理位置证明。R4B 与 R5 引用同一个环境变化事实时，留给计分层去重。

### R6 分片访问规律

只在同一访问上下文、同一媒体序列内计算，不能将多个观众拼成全视频的机械请求序列。

| 特征 | 计算口径 |
| --- | --- |
| unique_segment_count_obs / total_segments | 观测到的唯一分片数及对应媒体清单的总片数；不同版本/轨道分开 |
| coverage_ratio_obs | unique_segment_count_obs / total_segments；总体分母已知时，样本结果为覆盖下界 |
| monotonic_ratio_obs | 可确定顺序的相邻请求对中，分片序号严格递增的对数 / 有效对数；保留实际重试，不把相等当递增；没有原生顺序号时，仅使用两侧时间戳组均唯一的相邻对 |
| repeat_segment_count / backward_step_count | 重复请求同一媒体片，以及相邻序号回退的次数；不直接叫作复看/拖动次数 |
| request_gap_mean_ms / std_ms / interval_cv_obs | 按请求时间排序得到间隔，CV=总体标准差/均值；至少 3 个有时间记录的事件，均值>0才计算 CV |
| order_unknown_pair_count / timestamp_tie_count | 时间精度、排序不确定对数量，供规则检查数据质量 |

完整与采样序列分别标记，不能用同一命名口径假装已还原总体。样本能严格递增，也可能只是没抽到回退；缓存、正常预加载和顺序播放本来就可能规律。没有暂停、拖动等埋点时，不能输出 pause_count=0 或“无人类行为”。

### R7 视频失败请求过多

原生主体为视频，候选 10m 窗口，每分钟计算。先以 TS 鉴权结果为例，不混用不同请求阶段或来源。

| 特征 | 计算口径 |
| --- | --- |
| auth_pass_count_obs、auth_fail_count_obs、auth_unknown_count_obs | 同一视频/来源/阶段/窗口，按 PASS、FAIL、UNKNOWN 分别计数 |
| auth_known_result_count_obs | N=PASS+FAIL；未知不进入这个分母，但需展示未知占比 |
| auth_failure_ratio_obs | F/N，F=FAIL；N=0 返回 null，不返回 0% |
| failed_token_count_obs / failed_ip_count_obs | 失败事件关联的不同 token/IP 数；不代表真实攻击人数 |
| top1_failed_token_share_obs / top1_failed_ip_share_obs | 同口径下最大单来源失败量 / F；F=0 返回 null，样本比例不能直接当总体比例 |
| failure_reason_counts | 仅有明确业务原因时分类；无原因则 UNKNOWN，不从 false 猜过期或破解 |

候选规则条件仍为 N≥最小样本量 且 F≥失败量阈值 且 F/N≥失败率阈值。全量历史回放示例为 10m 内 N≥100、F≥30、比例≥20%；2 次全部失败不满足样本量，1,000 次中 40 次失败不满足比例，200 次中 50 次失败满足示例条件。生产阈值未定。

采样概率若按成功/失败不同，需要分别估计两类量再讨论总体比例；方式未知时仅输出样本比例。失败量增长可以另出历史比较特征，不能悄悄替换本规则的“数量与比例同时高”。

来源集中可辅助定位探测/重试，分散可辅助定位故障，但两者都不是确定归因。视频失败分不能直接成为盗版嫌疑分，也不分摊给全部观众。

### R8 长时间高强度访问

| 特征 | 计算口径 |
| --- | --- |
| active_minute_count_obs | 24h 内有符合声明成功层次内容访问的不同分钟桶数；样本下为活跃分钟下界 |
| longest_observed_active_minute_run | 连续有访问的分钟桶形成的最长段；采样只能给观测段，缺样可能截断 |
| max_observed_request_gap_s | 同一主体可归因请求按时间排序的最大间隔；样本可放大空白，不能当真实休息时间 |
| unique_media_seconds_24h / request_equivalent_seconds_24h | 沿用 R2 的并集与请求量定义分别计算，不混用 |
| active_minute_fraction_obs | active_minute_count_obs / 1,440；滚动完整 24h 为分母，窗口未具备覆盖时标记质量 |

没有事件的分钟只表示没有该口径网络访问，不能证明休息、暂停或离开。并行访问多视频的内容量可以相加，活跃分钟只能求时间桶并集，不能将多个视频的活跃时长直接相加。

### R9 异常时段活跃与夜间特征

单事件提取 local_hour、business_timezone、off_hours_config_version、is_off_hours。时区/时段配置缺失时 is_off_hours=null，不使用服务器本地时区代替。候选低活跃时段为业务本地时间 [02:00,06:00)，不是禁播时间。

时段标签本身可在时间已知时计算；R9 视频访问规则还要求视频已归属。成功、失败均可打标签，之后按结果层次分别聚合。标签 0 分，不按请求数加分。

| 后续特征 | 提取口径 |
| --- | --- |
| off_hours_event_count / active_video_count_obs | 24h 内同一主体带标签的事件数及视频数，分请求阶段/成功结果 |
| off_hours_active_minutes / longest_active_run | 按夜间事件使用 R8 的分钟桶口径，跨午夜不按日志文件断开 |
| off_hours_activity_ratio_obs | 同一 24h、主体、来源、阶段、结果口径的夜间事件数 / 全部事件数；分母为 0 返回 null，低样本保留门槛信息 |
| off_hours_speed_ratio | 预先定义的夜间观察窗口内按 R2 的媒体量/窗口秒数计算，不能把全天内容量除以夜间时长 |
| off_hours_baseline_median / off_hours_baseline_delta | 候选取最近 8 周、与当前日期相同星期几且严格早于本次夜间窗口的可比历史窗口，至少 4 个有效历史日；median 为同口径事件数中位数，delta=当前夜间事件数-median；未结束的当前夜间窗口只与历史相同已观察时段比较 |
| off_hours_baseline_multiplier / baseline_history_days | multiplier=当前同口径事件数/median，median=0 时返回 null / ZERO_BASELINE，另保留 delta；历史天数不足时返回不可计算。来源、采样、时区和结果口径需可比，不跨口径硬比较 |

历史比较本身是聚合特征，不改变 R9 单事件标签的性质。只采集夜间事件不足以算夜间占比，仍需同口径全天分母。

### R10 脚本或工具特征

| 特征 | 提取口径 |
| --- | --- |
| ua_family / tool_ua_match / tool_signature_code | 单事件解析，工具匹配保留模式、解析器版本和命中片段；空 UA、未知 UA 不直接判工具 |
| known_legitimate_tool_tag | 业务确认的合法工具/探活标签，与工具特征并存；不删除原始事实 |
| tool_event_count_obs / tool_request_stage_count_obs | 同一已关联会话或人+视频上下文内计数及阶段去重，不能混进整个租户的工具请求 |

工具 UA 可能合法也可伪装。高频、机械访问来自其他聚合特征，不能把“速度快”同时包装成 R2 与一个没有新增客户端证据的 R10。

## 8. 从一条 TS 事件到特征的操作顺序

1. 记录 source_record_ref 并获得稳定 event_id，重放时保持一致。
2. 按契约解析时间、布尔鉴权结果、IP、UA、URL 和 token；保留解析失败及未知值。
3. 生成 token_ref、credential_viewer_id、客户端类别、资源候选和时段标签。
4. 关联租户、标准视频/媒体时间轴，以及事件时点有效的 token 范围；关联不唯一就保留歧义，不编造 viewer_id 或会话。
5. 按同一来源/结果层次/身份依据分别更新 token、视频、人或凭证观众的窗口统计；不能对一次事件的多个候选会话重复更新。
6. 输出值、单位、分母、质量、版本和证据引用；规则读取这些特征后再判断阈值。

以下为合成的特征输出示例，不含真实 token：

```json
{
```

## 10. 提取验收样例

| 输入情况 | 期望输出 |
| --- | --- |
| 同一 source_record_ref 重放两次 | 观测计数只增加一次 |
| 同 token、同 URL、同毫秒，但不同真实请求/采集记录 | 不能仅靠内容 hash 合并；保留实际重试或重复不确定标记 |
| 相同 10 秒区间被请求 3 次 | 请求等价秒数 30，去重覆盖 10；实际传输/观看仍按各自证据 |
| 两种清晰度和音视频轨覆盖相同区间 | 按内容时间轴求并集，不将媒体时长翻倍 |
| 同 token 两环境各有通过事件 | 环境数下界≥2，未满足交错/记录量前不认定高档 |
| 两个 play_id 可能对应同一条 TS，无法唯一归属 | token/视频级计一次，会话级标歧义，不复制两次 |
| 5 分钟顺序访问 3 个视频 | 活跃视频数 3，不能据此输出并发数 3 |
| 失败结果缺失 | UNKNOWN 增加，FAIL 不增加；未知占比可见 |
| N=0 或只有未知结果 | 失败率 null / ZERO_DENOMINATOR，不输出 0% |
| 缺 m3u8 清单 | 请求计数可用，总片数/准确覆盖/媒体区间按依赖返回不可计算 |
| 采样未看到 key 或未看到某分片 | 不据此断言缺 key 或分片未请求 |
| 迟到 CDN 日志补齐 | 按原事件时间修正原窗口，保留旧版本及本次补算时刻 |
| token 当前已过期，但事件发生时有效 | 使用当时签发/续期历史，不回判成过期访问 |
| 只知道 token 绑定观众 | 输出凭证关联风险基础特征，实际操作者身份未知 |
| 夜间时段边界 | [02:00,06:00) 配置下 02:00 命中，06:00 不命中；缺时区/配置则不可判断 |

以上是提取验收条件，尚未对生产数据执行集成验证。字段映射和数据完整性经过验证后，才能宣称某项特征已具备生产计算条件。
