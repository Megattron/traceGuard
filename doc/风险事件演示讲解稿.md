# TraceGuard 风险事件演示讲解稿

本稿承接 [活动演示表达方案](活动演示表达方案.md)，按“业务场景 → 系统告警 → 观察事实 → 风险判断 → 分数解释 → 后续核查”的顺序讲述。面向非专业观众，不新增案例选择器或演示专用产品入口。

主案例依据当前[补充测试数据](演示案例测试数据.md)、本地告警快照及[计分卡 v0.2](计分卡-v0.2.md)。文中的告警编号来自当前本地快照；重新配置规则并检测后编号可能变化，以主体、视频和检测窗口定位事件。

## 1. 统一讲述方法

每个事件回答六个问题：

1. **客户担心什么？** 用一句业务语言说明，不先解释技术名词。
2. **系统在哪里发现？** 从风险大盘或告警中心筛选并打开正常告警记录。
3. **系统看见了什么？** 展示主体、时间范围、内容/环境事实和数据来源。
4. **为什么值得关注？** 说明与正常行为的差异，同时排除适用的合法业务场景。
5. **为什么是这个分数？** 先解释当前单规则分数；如介绍候选组合口径，再说明辅助证据、重复证据处理和封顶。
6. **客户接下来做什么？** 核查授权用途、账号使用、服务配置，记录复核依据。

给观众的术语翻译：token 是访问凭证，key 是解密所需的密钥，分片是视频的小段文件，聚合特征是把一段时间内分散的记录整理成行为特征。主视频优先使用这些业务说法，规则编号与统计缩写在需要时展开。

当前“系统捕捉”的真实实现范围：本地应用可读取合成验证数据、按窗口计算特征并保存告警与复核；客户日志接入和面向生产数据的持续检测调度尚未完成；当前仅支持服务运行期间对固定合成验证窗口自动轮巡。开场说明数据来源，不说本次告警来自实时客户日志。

## 2. 主事件：同一观众集中获取一门课程

**业务引入：**“即使用户拿到了正常访问凭证，也可能使用工具集中获取课程内容。客户需要知道，哪些访问值得进一步核查。”

**进入路径：**在当前运行版的告警中心搜索视频 `sim_course_01`，打开 R2 告警 `TG-D1CE59B67FF5`。本地快照的检测窗口为北京时间 2026-10-23 12:00–12:10，观众是 `sim_rapid_pull_case_supplement_viewer`。随后查看同一次检测、同一观众和视频的 R6 告警 `TG-ED50F87D996C` 与 R10 告警 `TG-149E817EF92D`。

**先展示三条事实：**

| 事实 | 面向普通观众的解释 | 当前特征依据 |
| --- | --- | --- |
| 10 分钟内获准访问 7,200 秒去重媒体内容 | 10 分钟里访问的内容长度相当于 2 小时；同一内容重复请求已去重 | TG-F03 / R2：速度比 12，A50 / S50 |
| 同会话按序访问 720/720 个分片 | 分片覆盖率和递增比例均为 100%，相邻请求间隔约 100 毫秒 | TG-F08 / R6：间隔 CV 0，A15 / S0 |
| 723 次工具特征请求，出现在 3 类请求阶段 | 同一活动多个阶段均出现 `ffmpeg/7.0` 特征 | TG-F12 / R10：A15 / S0 |

这组合成数据还有正常的 token、清单与 key 访问记录，720 个分片也有对应的 CDN 完整响应。它支持“服务端向该会话完整返回了这些分片”，不能据此断言客户端已在本地破解或传播内容。Key 响应与首个 TS 请求相隔仅 0.7 秒，两者 UA 均为 `ffmpeg/7.0`；本例没有“Key 后 UA 切换、间隔过长”的事实，不把 R1 链路异常算入案例。

**捕捉过程的讲法：**

> 系统将同一观众、视频和会话在 10 分钟内的记录关联起来，按媒体清单计算去重内容时长，再检查分片访问顺序与工具特征。演示租户已配置禁止下载和预取，因此 R2 的高速获取证据可以形成嫌疑分；R6 与 R10 是同一活动的辅助线索。

产品说明可称该事件为“疑似异常内容获取”。工具 UA 与响应记录仍不能证明已在本地解密、破解或传播。

**先讲当前应用实际显示的分数：**R2 为 A50 / S50；R6 和 R10 各为 A15 / S0。当前运行版逐规则保存告警，尚未把三条线索汇总成一个 S75。

**如介绍计分卡 v0.2 的跨规则候选演算，再拆解 75 分：**

| 计算步骤 | 分数 | 为什么这样处理 |
| --- | ---: | --- |
| 高速获取 | 50 | 主要嫌疑证据，满足当前候选阈值与准入条件 |
| 机械访问特征 | +15 | 同一活动的辅助证据 |
| 内容获取这一类证据封顶 | 65 → 60 | 相关证据互相补充，但限制同类行为对总分的影响 |
| 工具特征 | +15 | 与主要证据处于同一活动上下文 |
| 本例无反复片段加分 | +0 | 不因告警列表出现多个记录就自动重复计分 |
| **候选组合嫌疑分 S** | **75** | 计分卡设计值，当前应用尚未输出该汇总分 |

**讲述话术：**

> 目前告警中心已把高速获取评为 50 分，还能分别看到机械访问和工具特征。计分卡设计会把同类的 50 和 15 分封顶为 60，再加工具特征 15 分，得到候选组合分 75；这一步尚未接入当前应用。分数表达优先核查程度，不是盗版概率。

**下一步：**客户核对该账号是否有批量下载授权，查看相关活动和响应证据，在告警内留下处理依据。分数不会代替业务确认。

## 3. 共享使用线索：不同环境反复使用同一凭证

**业务引入：**“账号可以正常登录，但它的访问凭证可能被转给其他人使用。”

**进入路径：**告警中心搜索 `TG-20261023-0046`。该预置事件原生主体为凭证，直接在告警详情解释，无需恢复 token 计分卡 Tab。

**系统看见：**至少两个明显不同环境反复交错，跨度 180 秒，各至少 16 次鉴权通过，来源 IP 与客户端类别均不同。若展示详细环境轨迹，须使用相应明细或明确标注的模拟数据。

**如何捕捉：**TG-F06 把同一 token 的请求按时间及可信环境整理，检查环境数量、各自成功记录、返回与反复交错；先排除合法代理、允许的共享客户端及无效凭证。环境只是 IP 与客户端类别，不直接等于某台设备或某个人。

**如何计分：**R4B 的这项事实为 50 分。R5 即使因相同环境事实也命中 15 分，仍只取较高的 50 分，不能重复算成 65 分。本例嫌疑分为 50。

**讲述话术：**

> 我们没有看见 A 把账号交给 B 的动作，但看见同一凭证在不同环境中反复使用。这足以形成共享或泄漏线索。两条规则如果描述的是同一件事，只算一次，避免把同一证据重复放大。

如果只有凭证里绑定的观众 ID，个人行为仍显示身份待核实，不将凭证 50 分直接复制到观众身上。若两人分别登录获得不同 token，则改用账号环境和可靠并发证据，不能复用本例的同 token 规则。

## 4. 持续访问线索：全天访问大量课程

**当前状态：**现有原型尚无此预置事件，不能在录屏脚本中声称可找到。后续可将合成验证事件作为普通风险记录或观察线索加入，而非增加专用演示入口；是否生成告警由相应策略决定。

**数据要求：**24 小时记录完整、身份可靠、媒体映射可用，并分别统计成功访问活跃分钟、去重内容量、连续段和间隔。不能把最早和最晚请求之间的整段时间当作连续观看。

**示例条件：**若观测到至少 960 个活跃分钟，且去重内容量至少 16 小时，则命中当前 R8 辅助规则高档 15 分。若除此之外没有主要嫌疑证据、且数据足够判断，本例异常分 A=15，嫌疑分 S=0。

**讲述话术：**

> 这个账号的持续访问强度值得关注，但我们没有因此直接说它在录屏。系统先整理成观察线索，供客户核对培训安排、自动连播或其他合法用途。只有更多相关依据出现时，才进一步判断侵权风险。

这是减少误判的展示，不应为让第三个案例显得严重而给它虚构高嫌疑分。

## 5. 故障对照：失败很多，为什么不是高嫌疑

**进入路径：**告警中心搜索 `TG-20261023-0045`，打开视频 `V-DEMO-032`。

**系统看见：**10 分钟、同来源同 TS 鉴权阶段，500 次中失败 450 次，失败率 90%。TG-F09 将成功、失败与未知分开统计，并保留失败原因、来源集中度等解释字段。

**计算结果：**R7 高档，视频异常分 A=50；该事件没有其他准入的嫌疑证据，所以 S=0。

**讲述话术：**

> 这里同样出现很强的异常，但它只说明访问失败严重。服务故障或授权配置问题也可能导致这个结果，因此系统先提示排查，不把它自动算成盗版嫌疑。若进一步发现明确的范围外访问，才按对应授权证据另行判断。

失败率不能独立确诊故障；S=0 也不表示确认安全。最终确认需要错误原因、服务监控、配置及业务核验。

## 6. 原型需要支持的展示内容

保持风险大盘、告警中心、个人/视频计分卡和规则编辑器。案例通过正常列表搜索、筛选和大盘下钻找到。

告警详情建议按四块组织：

1. **发生了什么：**一句行为摘要，加主体、相关视频、观察窗口；用课程名称和账号显示名帮助理解，保留 ID 供追踪。
2. **系统依据：**原始统计值、通俗解释、来源/窗口、可追溯证据；只有相应明细齐备时才画回放或时间线。
3. **分数怎么算：**主要证据、辅助证据、同事实去重、同类上限、最终 S；A 单独展示。面向观众先讲贡献过程，规则编号与完整阈值展开查看。
4. **建议怎么核查：**尚未确认的事项、建议行动、人工复核依据和状态。

75 分、50 分和 0 分分别解释当前证据下的处置优先级与判断依据。数据不足的“—”必须与 0 分区分，不能通过动画把未知转成一个估算分。

## 7. 三分钟录制取舍

建议用 20 秒说明客户与演示数据范围，80 秒讲主事件与 75 分过程，30 秒讲共享线索与同事实去重，25 秒讲视频失败对照，最后 25 秒完成一次复核并说明客户数据接入及后续验证。

持续访问事件当前未补入，可先留在答辩说明中；若后续补入，可替换部分共享案例时长，不将四个事件都完整讲一遍。主视频避免展开数据库表名、全部 SQL 编号及统计缩写。

本次输出为讲解稿与展示内容约定，尚未修改原型或新增案例数据。
