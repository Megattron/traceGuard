## 设计与验收

- 独立 run_id；基础记录只读选取，token/观众使用稳定替代标识，合成事件、维度与来源策略明确标记 SYNTHETIC。10 月 23 日为按用户要求生成的未来模拟日期。
- 目标为百万级主验证事件，8 天每天有数据和完整 event_type 覆盖；另有小规模、明确分离的历史 fixture 验证夜间历史基线。主范围历史不足场景仍输出不可计算。
- 表和视图统一使用 da.tg_validation_ 前缀；特征 SQL 按 TG-F00～TG-F12 编号，与规则和输出字段一一索引。
- ClickHouse 版本以本次实际实例为准，已知 23.2.2.20；禁用该版本不支持的非等值普通 JOIN、arrayFold 等写法。
- 所有 SQL 接受 run_id、user_id、scenario_id、window_start、window_end 参数，窗口采用 [start,end)。scenario_id 空字符串表示该批次全部场景。
- 幂等：物理 record_id 与业务 event_id 分开。导入重复可用稳定 record_id 合并；明确的采集重放保留不同 record_id、相同 event_id，特征层再去重。原有数据不参与清理。
