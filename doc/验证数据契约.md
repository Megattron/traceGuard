# 隔离验证数据契约

本文件是生成器、特征 SQL 与独立验收共用的实现约定。run_id=`tg_980107c0ab_20261016_20261023_v1`，user_id=`980107c0ab`。主范围 `[2026-10-16 00:00:00,2026-10-24 00:00:00)`，时区 Asia/Shanghai。

## 表

实际列定义见 `../sql/validation/00_schema.sql`。所有隔离对象前缀为 `da.tg_validation_`。

- `events`：物理 record_id 幂等，event_id 表示业务事件，允许同 event_id 不同 record_id 的明确采集重放。auth_result 为 Int8：1=PASS、0=FAIL、-1=UNKNOWN。完整保留 event_type。
- `media_segments`：按原始资源 object_path 映射媒体位置；content_version 表示已确认可对齐的同一内容时间轴，跨清晰度/音视频轨按它求并集。
- `token_snapshots`：effective_at 时起生效，选事件之前最近快照，再检查 expires_at 半开有效期及 revoked。不能过滤掉过期快照后误选旧有效版本。
- `source_coverage`：按 scenario_id + event_type 记录覆盖区间、完整性与协议所需步骤；key_validity_seconds 与 request_activity_ttl_seconds 分列。历史零活动日也必须有覆盖记录才参与基线。
- `business_config`：每场景一个测试配置，Asia/Shanghai 或显式缺失；夜间分钟范围默认 [120,360)。
- `ip_info`：仅为合成文档地址提供测试地区/ISP，不解释为真实地理事实。

六张表使用 ReplacingMergeTree，按 run_id 与 record_id/row_key 去除重复导入；读逻辑数据用 FINAL。原 DWD 不更改。

## 公共视图

`da.tg_validation_events_dedup`：先读 events FINAL，再按 run_id/event_id 取 ingest_time、record_id 排序后的最后一条，区分导入幂等与业务采集重放。

`da.tg_validation_event_features`：上述去重事件 + 单事件派生字段：

- 原始 events 全部字段；client_ip=request_ip，另保留 viewer_ip/ip_basis。
- subject_type=`VIEWER`（AUTHENTICATED_VIEWER 且 viewer_id 有值）、`CREDENTIAL_VIEWER`（仅 credential_viewer_id）、`UNKNOWN`；subject_id 对应身份或 NULL。
- ua_family、os_family、sdk_family、env_ref、is_client_event、is_tool_ua、tool_signature_code、known_legitimate_tool、ua_parser_version。
- object_path、media_mapped、resource_version、content_version、playlist_ref、rendition_ref、track_type、segment_index、media_start_s、media_end_s、segment_duration_s、total_segments、expected_object_bytes。
- business_timezone、config_matched、local_hour、local_minute_of_day、is_off_hours。
- fully_served：CDN 响应状态/完成标记/对象大小与完整范围足以证明服务端完整响应时为1；明确不完整为0；必要字段缺失为NULL。

环境比较优先 is_client_event=1；TOKEN_CREATE/TOKEN_RENEW 等后端调用不作为播放器 UA。未知 UA/IP 不生成可信 env_ref。所有元数据及模拟身份带 dataset_kind，不伪装成源观测。

## SQL 参数与输出

每个 TG-Fxx SQL 为一条只读 SELECT，可含 WITH；使用 ClickHouse HTTP 参数：

```text
{run_id:String}, {user_id:String}, {scenario_id:String},
{window_start:DateTime64(3)}, {window_end:DateTime64(3)}
```

scenario_id='' 表示整批。所有主统计均 `[window_start,window_end)`；前置授权、状态和历史基线可读 window_start 之前本批数据，不能读 window_end 之后事实影响过去。

按自然主体输出宽特征列，保留 run_id/user_id/subject_type/subject_id/window_start/window_end、compute_status/reason_code/value_kind 及必要分母/未知量。复杂组允许额外 feature-specific 状态列，不能用全组 AVAILABLE 掩盖某个不可计算项。

编号固定：TG-F00质量、F01单事件、F02链路、F03内容、F04多视频、F05范围、F06token环境、F07主体环境、F08分片规律、F09失败、F10持续访问、F11夜间、F12工具。英文列名沿用特征设计，兼容少量明确解释的辅助列。
